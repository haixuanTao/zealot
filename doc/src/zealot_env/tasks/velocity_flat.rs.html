1//! **Flat velocity tracking** for the LeRobot bipedal — the first milestone:
2//! reproduce, in Rust on nexus, the deployed
3//! `Mjlab-Velocity-Flat-LeRobot-Humanoid-no-arms` policy.
4//!
5//! The robot walks on flat ground tracking a commanded planar velocity
6//! `(vx, vy, yaw_rate)`. This file is the *task config* (Isaac Lab tier): the
7//! observation layout, the action→joint-target map, the reward terms with their
8//! weights, the command sampler, and the termination rule — ported from the
9//! mjlab config of that policy and AGILE's T1 velocity task.
10//!
11//! It is pure CPU code over [`RobotState`]; the env loop fills that struct from
12//! nexus readback (`dof_values`/`dof_state` + base pose/velocity) and applies the
13//! [`VelocityFlatTask::joint_targets`] output through the joint PD controllers.
14//!
15//! ## Frame convention (Z-up)
16//!
17//! The env runs Z-up, matching the MuJoCo model and the real robot: base axes
18//! **forward = +X, lateral = +Y, up = +Z**; yaw is rotation about +Z. (Verified
19//! against the spawned MJCF stance in `biped_mjcf`.)
20//!
21//! ## Reward terms
22//!
23//! Proprioceptive terms (velocity/yaw tracking, upright, posture, symmetry,
24//! action-rate, joint penalties) and the **foot-contact** terms (feet air-time,
25//! foot-slip, foot-clearance) are all live — the env fills [`FootObs`] from the
26//! simulator's contacts. A few minor deployed terms remain unimplemented
27//! (action-FFT smoothness band, angular-momentum, soft-landing) and
28//! self-collision is N/A here (only the feet carry colliders).
29

41/// Observation vector length (policy group): `last_action(12) + command(4) +
42/// joint_pos_rel(12) + joint_vel(12) + projected_gravity(3) + gait_phase(2)`.
43/// The trailing 2 are (sin 2πφ, cos 2πφ) of the gait clock so the policy can
44/// time its steps to the periodic gait reward.
45// `+ 3` at the end is the base ANGULAR VELOCITY (gyro). Added after v21: the
46// actor had no rotation sense at all — angular velocity was critic-only
47// privileged information — so yaw control was open-loop and the policy could
48// not cancel even its own heading drift (measured: yaw output scattered
49// positive regardless of commanded sign). Every deployed locomotion stack
50// feeds the gyro to the policy; it is free on hardware (IMU).
51// `+ 5` at the very end is the STEP CUE (slots 48-52): distance to the edge,
52// its signed height, the edge ORIENTATION as (sin, cos) in the body frame, and
53// a validity flag. Supplied on hardware by a head RealSense: a plane fit plus
54// edge extraction yields all three quantities directly, and unlike a foot
55// probe it gives the edge DIRECTION -- which is what lets the robot meet a
56// step at an angle rather than only head-on. Trained against a terrain oracle
57// with sensor-shaped noise (see `StepCue`).
58// `+ 2*NUM_HELD_OBS` at the very end (slots 53..79): the UPPER-BODY block —
59// the 13 held-joint PD TARGETS and their finite-diff velocities. Until now the
60// policy was blind to the arms: the AMASS playback moved 13 joints of mass and
61// the legs only found out via the gyro, one control step after the torso
62// already started tipping. Targets, not measured angles, on purpose: the
63// controller COMMANDS the arms, so targets are exactly known on hardware too,
64// and they LEAD the physical motion — feedforward, not just faster feedback.
65// Zero-padded (targets = home, vel = 0) when the robot has fewer held joints
66// or playback is off.
67pub const NUM_HELD_OBS: usize = 13;
68pub const OBS_DIM: usize =
69    NUM_JOINTS + 4 + NUM_JOINTS + NUM_JOINTS + 3 + 2 + 3 + 5 + 2 * NUM_HELD_OBS;
70/// Action vector length: one position target per leg DOF.
71pub const ACTION_DIM: usize = NUM_JOINTS;
72/// Privileged (critic) observation length: policy obs plus base linear & angular
73/// velocity in the body frame. Foot/contact privileged terms are deferred.
74// `+ 5` is the CLEAN step cue: the critic always sees the true edge state,
75// un-noised and never dropped, even while the ACTOR's copy (slots 48..53 of
76// the policy obs) is heavily dropout-masked early in training. Asymmetric
77// actor-critic: the value function credits crossing correctly on steps the
78// actor could not see, so the gradient learns "crossing pays" from blind
79// practice -- the fix for the observed cue->caution trap, where a policy
80// that has not yet learned to climb treats the cue purely as a fall
81// predictor and stops.
82pub const CRITIC_OBS_DIM: usize = OBS_DIM + 3 + 3 + 5;

121/// Per-foot state needed by the contact-shaped rewards. The env fills this from
122/// the simulator's contacts; `air_time` is tracked across steps by the env.
123#[derive(Clone, Copy, Debug)]
124pub struct FootObs {
125    /// Foot is touching the ground this step.
126    pub contact: bool,
127    /// Touchdown this step (was airborne last step, now in contact).
128    pub first_contact: bool,
129    /// Seconds the foot has been airborne (0 while in contact).
130    pub air_time: f32,
131    /// Foot world height, m.
132    pub height: f32,
133    /// Foot horizontal speed, m/s (for slip / clearance shaping).
134    pub planar_speed: f32,
135    /// Sole tilt from horizontal, rad (0 = sole flat on the ground). Used by the
136    /// flat-foot reward so the robot plants its whole sole, not an edge/toe/heel.
137    pub tilt: f32,
138    /// Foot yaw RELATIVE to the base (rad; 0 = foot points the same direction as
139    /// base). Computed by the env as `atan2(y, x)` of `q_base⁻¹·q_foot · X̂`. Used
140    /// by `feet_yaw_mean`.
141    pub yaw_rel_base: f32,
142    /// Foot world horizontal position (m). The reward uses the difference between
143    /// the two feet's positions, transformed into the base frame, to compute the
144    /// lateral stance width.
145    pub pos_xy: [f32; 2],
146    /// Touchdown this step that ALTERNATED feet — `first_contact` AND the *other*
147    /// foot was the most recent to touch down (set by the env, which tracks the
148    /// last-touchdown foot per env). The swing/air-time reward keys off this so a
149    /// step only pays when feet alternate (L→R→L→R): a foot held permanently in
150    /// the air never touches down (no reward), and double-tapping the same foot
151    /// (hopping) earns nothing on the repeat. Forces a real alternating gait.
152    pub alt_step: bool,
153    /// Foot vertical velocity, m/s (world +Z; negative = descending). Env
154    /// finite-diff, 0 on the first step after reset. Drives the
155    /// `touchdown_vz` slam penalty — the KINEMATIC impact term (a slam is a
156    /// foot still descending fast near the ground; kinematics transfer
157    /// across engines far better than contact-sensor forces do).
158    pub vz: f32,
159    /// One-step change in this foot's sensed normal contact force, in BODY
160    /// WEIGHTS per control step (|F_t − F_{t−1}| / (m·g), ≥ 0). Filled by the
161    /// env from the contact-force sensor (BIPED_CONTACT_SENSE); 0 when force
162    /// sensing is off or on the first step after a reset. Drives the
163    /// `force_rate` ground-reaction-smoothness penalty: a hard touchdown is a
164    /// 1–2 BW jump in one step, and the standing tremor is a sustained
165    /// left/right load dither — both are pure force-rate, while calm standing
166    /// and normal gait weight transfer (~0.06–0.12 BW/step) are ~free.
167    pub force_rate: f32,
168}

189/// What the head RealSense reports about the step ahead.
190///
191/// Extraction is a SCRIPTED perception step, not something the policy learns:
192/// a plane fit plus edge detection on the depth image yields distance, height
193/// and edge orientation directly. The policy's job is only to EXECUTE the step
194/// given those numbers -- which is why this is 5 floats into the existing MLP
195/// rather than a CNN on raw depth.
196///
197/// `valid = 0` must mean "no step information" and the policy must walk
198/// normally on it -- otherwise a dropped detection on hardware becomes a fall
199/// rather than a refusal.
200#[derive(Clone, Copy, Debug, Default)]
201pub struct StepCue {
202    /// Horizontal distance from the stance to the edge, m. Meaningless when
203    /// `valid == 0`.
204    pub distance: f32,
205    /// Signed height of the surface beyond the edge, m. Positive = step UP,
206    /// negative = step DOWN.
207    pub height: f32,
208    /// Edge normal direction in the BODY frame, as (sin, cos) of the angle
209    /// between the robot's heading and the edge normal. (0, 1) means the edge
210    /// is square-on. Split into sin/cos rather than a raw angle so it is
211    /// continuous across the +/-pi wrap, and so the mirror transform is a
212    /// clean sign flip on sin alone.
213    pub edge_sin: f32,
214    pub edge_cos: f32,
215    /// 1.0 when a detection succeeded, 0.0 otherwise (no step, or no reading).
216    pub valid: f32,
217}

219#[derive(Clone, Copy, Debug)]
220pub struct RobotState {
221    /// Base link state.
222    pub base: BaseState,
223    /// Joint positions, rad, in canonical joint order.
224    pub joint_pos: [f32; NUM_JOINTS],
225    /// Joint velocities, rad/s, in canonical joint order.
226    pub joint_vel: [f32; NUM_JOINTS],
227    /// Previous policy action (this step's `actions` observation).
228    pub last_action: [f32; NUM_JOINTS],
229    /// Action before that (for the action-rate-of-rate term).
230    pub prev_action: [f32; NUM_JOINTS],
231    /// Action before THAT — third point for the true second difference
232    /// (`action_rate_rate` = Σ(a − 2a' + a″)²), the action-side tremor
233    /// penalty: dither is action oscillation, so it's priced at the source
234    /// with no contact sensor in the loop (the sensor-side force_rate term
235    /// bred a straight-leg, transfer-breaking gait).
236    pub prev2_action: [f32; NUM_JOINTS],
237    /// Per-foot contact state (left, right).
238    pub feet: [FootObs; NUM_FEET],
239    /// Gait-clock phase ∈ [0,1), advanced by the env each control step. Drives
240    /// the periodic gait reward (foot 0 should swing near phase 0, foot 1 near
241    /// phase 0.5) and is fed to the policy as (sin 2πφ, cos 2πφ) so it can lock
242    /// its leg motion to the clock. The phase-clock reward provides a DENSE
243    /// per-step gradient toward an alternating swing/stance pattern — which the
244    /// sparse touchdown bonus (air_time) could not, since a step's payoff never
245    /// beat the fall risk (the shuffle stayed a stable local optimum).
246    pub phase: f32,
247    /// Latest step-cue report AS THE ACTOR SEES IT (noised, dropout-masked).
248    pub step_cue: StepCue,
249    /// The clean oracle cue, critic-only (asymmetric AC). Zero when unknown.
250    pub step_cue_clean: StepCue,
251    /// Held-joint (upper body) PD targets, staging order. Home pose when
252    /// playback is off; zero-padded past the robot's held-joint count.
253    pub held_pos: [f32; NUM_HELD_OBS],
254    /// Finite-diff velocity of `held_pos` (per control step / dt).
255    pub held_vel: [f32; NUM_HELD_OBS],
256}

277/// A commanded planar base velocity.
278#[derive(Clone, Copy, Debug, Default, PartialEq)]
279pub struct VelocityCommand {
280    /// Forward velocity, m/s.
281    pub vx: f32,
282    /// Lateral velocity, m/s.
283    pub vy: f32,
284    /// Yaw rate, rad/s.
285    pub yaw_rate: f32,
286}

288impl VelocityCommand {
289    /// The 4-channel command observation `[vx, vy, yaw_rate, aux]`. The 4th
290    /// channel is reserved (0.0) so the layout matches the deployed policy's
291    /// 4-wide `twist` command until its exact meaning is reconciled.
292    #[inline]
293    pub fn obs(&self) -> [f32; 4] {
294        [self.vx, self.vy, self.yaw_rate, 0.0]
295    }
296
297    /// Commanded planar speed (used for posture gating / zeroing).
298    #[inline]
299    pub fn speed(&self) -> f32 {
300        (self.vx * self.vx + self.vy * self.vy + self.yaw_rate * self.yaw_rate).sqrt()
301    }
302}

314    pub ang_vel_z: (f32, f32),
315    /// Probability a resample yields a standing (all-zero) command.
316    pub standing_prob: f32,
317    /// `(min, max)` resample interval, seconds.
318    pub resample_s: (f32, f32),
319}

321/// Parse an env var holding a `"lo,hi"` range, e.g. `BIPED_YAW="-0.5,0.5"`.
322fn range_env(var: &str, default: (f32, f32)) -> (f32, f32) {
323    std::env::var(var)
324        .ok()
325        .and_then(|s| {
326            let p: Vec<f32> = s.split(',').filter_map(|x| x.trim().parse().ok()).collect();
327            (p.len() == 2).then(|| (p[0], p[1]))
328        })
329        .unwrap_or(default)
330}

332impl Default for CommandSampler {
333    fn default() -> Self {
334        // From the deployed Mjlab-Velocity-Flat-LeRobot config.
335        Self {
336            // Reachable at our budget: 0.5 m/s is achievable, 0.8 is not. With an
337            // unreachable max command the curriculum forces the policy into a
338            // regime where tracking reward is uniformly tiny → it gives up.
339            // Override per-axis with BIPED_VX / BIPED_VY / BIPED_YAW ("lo,hi").
340            lin_vel_x: range_env("BIPED_VX", (-0.8, 0.8)),
341            lin_vel_y: range_env("BIPED_VY", (-0.5, 0.5)),
342            // Yaw was ±0.2 through v21 — 5× narrower than WBC-AGILE T1's ±1.0,
343            // and too narrow to learn from: at |yaw| ≤ 0.2 the exp tracking
344            // kernel is nearly satisfied by NOT turning, so `track_ang_vel`
345            // earned only 0.006/step (13% of linear tracking) and v21 turned
346            // the WRONG WAY on a commanded ±0.2 (measured +0.03 / +0.02 rad/s
347            // for ±0.5, −0.05 for +0.2). Raising the weight 5→8 had already
348            // failed to fix it — the problem is the command range, not the
349            // price. ±0.6 gives the kernel something to discriminate while
350            // staying inside what the 12-DOF platform can turn.
351            // NOTE evaluations: ±0.5 was OUTSIDE the old training range, so
352            // every pre-v22 yaw probe at 0.5 was measuring extrapolation.
353            ang_vel_z: range_env("BIPED_YAW", (-1.0, 1.0)),
354            // Fraction of command resamples that are a pure STAND (zero). Raising
355            // it (BIPED_STAND_PROB) makes the robot stop more often → trains
356            // explicit walk→stand→walk (go-stop-go) transitions and gives frequent
357            // quasi-static "stabilize" checkpoints (helps the deliberate gait +
358            // transfer). Resample interval (BIPED_RESAMPLE_S, "lo,hi" seconds);
359            // shorter = more frequent transitions.
360            standing_prob: std::env::var("BIPED_STAND_PROB")
361                .ok()
362                .and_then(|s| s.parse().ok())
363                .unwrap_or(0.1),
364            resample_s: std::env::var("BIPED_RESAMPLE_S")
365                .ok()
366                .and_then(|s| {
367                    let p: Vec<f32> = s.split(',').filter_map(|x| x.parse().ok()).collect();
368                    if p.len() == 2 {
369                        Some((p[0], p[1]))
370                    } else {
371                        None
372                    }
373                })
374                .unwrap_or((8.0, 12.0)),
375        }
376    }
377}

379impl CommandSampler {
380    /// Draw a fresh command.
381    pub fn sample(&self, rng: &mut Lcg) -> VelocityCommand {
382        if rng.chance(self.standing_prob) {
383            return VelocityCommand::default();
384        }
385        let mut cmd = VelocityCommand {
386            vx: rng.range(self.lin_vel_x.0, self.lin_vel_x.1),
387            vy: rng.range(self.lin_vel_y.0, self.lin_vel_y.1),
388            yaw_rate: rng.range(self.ang_vel_z.0, self.ang_vel_z.1),
389        };
390        // Low-speed mass (BIPED_SLOW_PROB, default 0.25): uniform range
391        // sampling puts almost no probability on SLOW commands relative to
392        // the reward's sharp kernel, and the terrain curriculum pays for
393        // travel — the 30k-iter policy learned exactly two speeds (0 and
394        // ~±1 m/s), saturating every magnitude in between. Slow draws are
395        // rescaled onto a speed in [0.12, 0.3]: the quasi-static regime where
396        // single-support balance is hardest (and sim2sim falls live), kept
397        // strictly above the 0.1 standing threshold so the gait clock runs.
398        let slow_prob: f32 = std::env::var("BIPED_SLOW_PROB")
399            .ok()
400            .and_then(|s| s.parse().ok())
401            .unwrap_or(0.5);
402        // Arc bias (BIPED_ARC_PROB, default 0.25): with the yaw range widened
403        // to +/-0.6, independent uniform draws still put almost no mass on
404        // CURVED walking -- measured only ~5% of moving commands were strong
405        // arcs (|yaw|>=0.15 with |vx|>=0.3). Explicitly pair a real forward
406        // speed with a real yaw rate so turning-while-walking is in the data
407        // at all, not just turning-in-place.
408        let arc_prob: f32 = std::env::var("BIPED_ARC_PROB")
409            .ok()
410            .and_then(|s| s.parse().ok())
411            .unwrap_or(0.25);
412        if rng.chance(arc_prob) {
413            let sx = if rng.chance(0.5) { 1.0 } else { -1.0 };
414            let sy = if rng.chance(0.5) { 1.0 } else { -1.0 };
415            cmd.vx = sx * rng.range(0.25, self.lin_vel_x.1.abs().max(0.25));
416            cmd.yaw_rate = sy * rng.range(0.2, self.ang_vel_z.1.abs().max(0.2));
417            cmd.vy = 0.0;
418            return cmd;
419        }
420        if rng.chance(slow_prob) {
421            let target = rng.range(0.12, 0.3);
422            let speed = cmd.speed();
423            if speed > 1e-6 {
424                let k = target / speed;
425                cmd.vx *= k;
426                cmd.vy *= k;
427                cmd.yaw_rate *= k;
428            }
429        }
430        // A draw below the 0.1 standing threshold is contradictory: the gait
431        // clock freezes and stand_planted engages while tracking still asks
432        // for motion. Snap it to a true stand.
433        if cmd.speed() < 0.1 {
434            return VelocityCommand::default();
435        }
436        cmd
437    }
438
439    /// Draw a resample interval in control steps, given the control dt.
440    pub fn resample_steps(&self, rng: &mut Lcg, control_dt: f32) -> u32 {
441        (rng.range(self.resample_s.0, self.resample_s.1) / control_dt).round() as u32
442    }
443}

445/// Reward term weights (per-second; the task scales by the control dt). Defaults
446/// are the deployed policy's. `deferred_*` weights are recorded for parity but
447/// their terms aren't summed yet (they need contact readback).
448#[derive(Clone, Copy, Debug)]
449pub struct RewardWeights {
450    /// Linear-velocity tracking (exp kernel), `std` below.
451    pub track_lin_vel: f32,
452    /// Linear forward-progress reward: `w · clamp(v·ĉmd, 0, |cmd|)`. A non-saturating
453    /// gradient toward the commanded direction (breaks the march-in-place dead zone
454    /// where the exp tracking kernel is flat). Folded into the `track_lin_vel` term.
455    pub forward_progress: f32,
456    /// Angular (yaw) velocity tracking (exp kernel).
457    pub track_ang_vel: f32,
458    /// Upright / flat-orientation (exp kernel on tilt).
459    pub upright: f32,
460    /// Base-height tracking (exp kernel) — keeps the robot standing tall instead
461    /// of crouching to trivially avoid falling.
462    pub base_height: f32,
463    /// Target base (torso) height, m (for `base_height`) while MOVING.
464    pub base_height_target: f32,
465    /// Target base height, m, while STANDING (`cmd.speed() < 0.1`, the same gate
466    /// the gait clock freezes on). Defaults to `base_height_target`, so the
467    /// split is inert until `BIPED_BASE_HEIGHT_STAND` is set.
468    ///
469    /// Standing tall is nearly free in height but expensive in knee angle:
470    /// measured on this robot, height = 0.580*cos(knee/2) + 0.259, so the leg
471    /// ceiling is 0.839 m at knee 0 and the curve goes FLAT as it straightens
472    /// (15 deg -> 0 deg of knee buys only 5 mm). Two consequences:
473    ///   * a target ABOVE ~0.839 is unreachable without hyperextending into the
474    ///     -0.087 rad knee stop. That is what v22 did at 0.841 (locked at -4 deg,
475    ///     60% of frames on the stop, CoT 1.00) -- do not set one.
476    ///   * above ~0.837 the gradient falls under 0.5 mm/deg, so the only way to
477    ///     chase the last millimetres is to ride the stop.
478    /// 0.835 -> ~13.6 deg knee with 18.6 deg of stop margin, 4 mm under the
479    /// ceiling: reachable at a legal knee angle, unlike v22's target.
480    pub base_height_target_stand: f32,
481    /// Hip yaw/roll deviation penalty gain (NEGATIVE). L2 penalty on hipz+hipx
482    /// deviation from default, always-on — stops the policy from limit-riding the
483    /// lateral hips into a splayed brace. (Was an unused full-posture reward.)
484    pub pose: f32,
485    /// Left/right symmetry (exp kernel on mirror error).
486    pub bilateral_symmetry: f32,
487    /// L2 penalty on action change.
488    pub action_rate: f32,

545    /// foot-slam touchdowns (measured 0.9 BW mean / 2.1 BW peak first-contact
546    /// jumps in MuJoCo) and the standing tremor (left/right load share
547    /// dithering 0→1 at ~18 Hz with both feet planted — invisible in base

549    /// weight transfer (~0.06–0.12 BW/step) free, so walking itself is not

551    pub force_rate: f32,
552    /// Deadband for `force_rate`, body weights per control step (default 0.15).
553    pub force_rate_deadband: f32,
554    /// Foot-clearance penalty (swing-foot height vs target).
555    pub foot_clearance: f32,
556    /// Target swing-foot clearance height, m (for `foot_clearance`).
557    pub foot_clearance_target: f32,
558    /// Flat-foot penalty: penalizes sole tilt (rad²) of a foot IN CONTACT, so the

560    pub foot_orientation: f32,
561    /// WBC's `feet_yaw_mean_vs_base`: penalty on each foot's yaw (in base frame),

573    pub feet_distance_ref: f32,

957        // bent-knee height target (NOT the per-robot straight-leg default).
958        // Pair with BIPED_POWER_W=0 (AGILE has no power term).
959        let agile_rewards = std::env::var("BIPED_AGILE_REWARDS").is_ok_and(|v| v == "1");
960        if agile_rewards {
961            println!(
962                "AGILE reward parity ENABLED: WBC-AGILE G1 term set (no stepping rewards), \
963                 stds lin/ang 0.2, height target 0.72"
964            );
965        }
966        let mut weights = if agile_rewards {
967            RewardWeights::agile()
968        } else {
969            RewardWeights::default()
970        };
971        // The base-height target is per-robot (lerobot trunk 0.72 m, G1 pelvis
972        // 0.78 m, H2 Plus pelvis 1.03 m); the RewardWeights default keeps the
973        // lerobot value for struct-literal users.
974        if !agile_rewards {
975            weights.base_height_target = robot.base_height;
976        }
977        let env_f32 = |k: &str| std::env::var(k).ok().and_then(|s| s.parse::<f32>().ok());
978        if let Some(v) = env_f32("BIPED_W_TRACK_LIN") {
979            weights.track_lin_vel = v;
980        }
981        if let Some(v) = env_f32("BIPED_W_TRACK_ANG") {
982            weights.track_ang_vel = v;
983        }
984        if let Some(v) = env_f32("BIPED_W_UPRIGHT") {
985            weights.upright = v;
986        }
987        if let Some(v) = env_f32("BIPED_W_BASE_H") {
988            weights.base_height = v;
989        }
990        // Target height for the base_height kernel. AGILE's 0.72 is a
991        // bent-knee stance; measured v21 sits 4-9 cm BELOW even that
992        // (0.63-0.68 m vs 0.79 natural) because crouching buys balance
993        // stability and the wide sigma=0.1 kernel makes the undershoot
994        // cheap. 0.75 is the recommended first step up; 0.78+ risks the
995        // straight-knee singularity where the leg loses vertical control
996        // authority.
997        // NOTE: BIPED_BASE_HEIGHT sets BOTH targets, so the historical
998        // single-knob behaviour is preserved exactly. BIPED_BASE_HEIGHT_STAND
999        // is applied AFTER it and overrides the standing one only -- order
1000        // matters, do not reorder these two blocks.
1001        if let Some(v) = env_f32("BIPED_BASE_HEIGHT") {
1002            weights.base_height_target = v;
1003            weights.base_height_target_stand = v;
1004        }
1005        // Command-conditioned standing height. The policy already prefers a
1006        // taller stance than its gait (v24 measured 0.816 standing vs 0.807
1007        // walking), so this codifies an existing preference rather than
1008        // fighting one. See the field docs for the knee-angle geometry and why
1009        // anything above ~0.837 rides the knee stop.
1010        weights.base_height_target_stand =
1011            env_f32("BIPED_BASE_HEIGHT_STAND").unwrap_or(weights.base_height_target + 0.01);
1012        // AGILE-alignment override: WBC has NO air-time reward — its gait
1013        // economy comes from torque/energy regularizers. Paying completed
1014        // swing DURATION (capped 0.4s ≈ our natural swing) selects for
1015        // maximal, exaggerated swings once a gait exists. 0 = AGILE parity.
1016        if let Some(v) = env_f32("BIPED_W_AIR_TIME") {
1017            weights.air_time = v;
1018        }
1019        let mut stds = if agile_rewards {
1020            RewardStds::agile()
1021        } else {
1022            RewardStds::default()
1023        };
1024        if let Some(v) = env_f32("BIPED_STD_LIN") {
1025            stds.lin_vel = v;
1026        }
1027        // Width of the height kernel (BIPED_STD_BASE_H, metres). The default
1028        // 0.1 is wide enough that a 4 cm undershoot still collects 85% of the
1029        // reward, which is why v21 sat 4 cm below its own target and stayed
1030        // there. Tightening to ~0.05 makes a crouch cost the height reward
1031        // outright -- the direct way to price posture, instead of taxing knee
1032        // torque and hoping the posture follows.
1033        stds.base_height = env_f32("BIPED_STD_BASE_H").unwrap_or(0.05);
1034        // Width of the ANGULAR tracking kernel. The default 0.1 is far too
1035        // narrow for the +/-0.6 command range: a policy sitting at the measured
1036        // 0.06 rad/s scores exp(-(0.4-0.06)^2/0.1^2) = 1e-5 on a 0.4 command,
1037        // i.e. NO gradient to climb. Measured on v24 at iter 32-42k, which
1038        // never learned to turn despite the gyro, the widened yaw range and 25%
1039        // arc sampling -- the arcs sample yaw in [0.2, 0.6], of which only the
1040        // 0.2 edge pays anything at all (14%; 0.35 pays 0.02%).
1041        //
1042        // v22 DID turn (+0.38) because it happened to land inside the basin,
1043        // after which a 0.4 command scores 96% and self-reinforces. That is
1044        // luck, not a gradient. 0.3 makes a 0.4 command pay 28% from a standing
1045        // start, so there is a slope the whole way in.
1046        stds.ang_vel = env_f32("BIPED_STD_ANG").unwrap_or(0.3);
1047        // Action-rate penalty gain (NEGATIVE). Exposed because it is denominated
1048        // in ACTION units, not radians: it charges (delta action)^2, so halving
1049        // BIPED_ACTION_SCALE makes the same PHYSICAL motion cost 4x more here.
1050        // Anyone running action_scale 0.25 must scale this by ~1/4 or the
1051        // penalty dominates and the policy simply stops moving.
1052        if let Some(v) = env_f32("BIPED_W_ACTION_RATE") {
1053            weights.action_rate = v;
1054        }
1055        Self {
1056            robot,
1057            weights,
1058            stds,
1059            sim_dt: 1.0 / 200.0,
1060            decimation: 4,
1061            episode_s: 20.0,
1062            tilt_limit: 70.0_f32.to_radians(),
1063            min_base_height: robot.min_base_height,
1064            hip_yawroll_idx,
1065            sym_yaw_gate: env_f32("BIPED_SYM_YAW_GATE").unwrap_or(0.0),
1066            step_relax_dist: env_f32("BIPED_STEP_RELAX_DIST").unwrap_or(0.6),
1067            step_std_base_h: env_f32("BIPED_STEP_STD_BASE_H").unwrap_or(0.15),
1068            step_std_upright: env_f32("BIPED_STEP_STD_UPRIGHT")
1069                .unwrap_or(25.0_f32.to_radians()),
1070        }
1071    }

1085    /// Map a policy action to per-joint PD position targets:
1086    /// `q_target = default_pos + action_scale · action`.
1087    pub fn joint_targets(&self, action: &[f32; NUM_JOINTS]) -> [f32; NUM_JOINTS] {
1088        std::array::from_fn(|i| {
1089            let j = self.robot.joints[i];
1090            // Clamp the PD target to the joint's physical limit. Unbounded targets
1091            // let the policy command far past the stops (measured: hipx target
1092            // ~1.5 rad vs a ±0.35 rad limit), so the PD slams the joint into its
1093            // limit at near-saturated torque every step. That "limit-riding" pose
1094            // is a degenerate local optimum: it wastes torque (critically on the
1095            // fragile ankle) and gives the policy a flat, zero-gradient region to
1096            // get stuck in — every trained policy collapsed to it. Clamping keeps
1097            // the commanded pose physical and the PD error (hence torque) bounded,
1098            // while still allowing each joint its FULL range (the action scale,
1099            // not ±1, sets how far |action| must go to reach the limit).
1100            let (lo, hi) = j.pos_limit;
1101            (j.default_pos + j.action_scale * action[i]).clamp(lo, hi)
1102        })
1103    }

1134    /// Assemble the 43-dim policy observation into `obs`.
1135    ///
1136    /// Layout: `[last_action(12), command(4), joint_pos_rel(12), joint_vel(12),
1137    /// projected_gravity(3), gait_clock(2), base_ang_vel(3)]`.
1138    /// `joint_pos_rel = q − default_pos`.
1139    pub fn observe(&self, state: &RobotState, cmd: &VelocityCommand, obs: &mut [f32]) {
1140        debug_assert_eq!(obs.len(), OBS_DIM);
1141        let mut o = 0;
1142        let put = |obs: &mut [f32], o: &mut usize, v: f32| {
1143            obs[*o] = v;
1144            *o += 1;
1145        };
1146        for i in 0..NUM_JOINTS {
1147            put(obs, &mut o, state.last_action[i]);
1148        }
1149        for c in cmd.obs() {
1150            put(obs, &mut o, c);
1151        }
1152        for i in 0..NUM_JOINTS {
1153            put(
1154                obs,
1155                &mut o,
1156                state.joint_pos[i] - self.robot.joints[i].default_pos,
1157            );
1158        }
1159        for i in 0..NUM_JOINTS {
1160            put(obs, &mut o, state.joint_vel[i]);
1161        }
1162        for g in self.projected_gravity(&state.base) {
1163            put(obs, &mut o, g);
1164        }
1165        // Gait clock as (sin, cos) so it's continuous across the 1→0 wrap.
1166        let ph = state.phase * std::f32::consts::TAU;
1167        put(obs, &mut o, ph.sin());
1168        put(obs, &mut o, ph.cos());
1169        // Base angular velocity (body frame). Kept LAST so the preceding 45
1170        // slots keep their v21 meaning — the mirror transform, the sim2sim
1171        // harnesses and the lerobot controller all index by position.
1172        for w in self.base_ang_vel_body(&state.base) {
1173            put(obs, &mut o, w);
1174        }
1175        // Step cue LAST, so slots 0-47 keep their v22-v27 meaning. Distance is
1176        // clipped: beyond ~1.5 m the exact value carries no useful information
1177        // and an unclipped range would waste normalizer resolution on it.
1178        // When `valid == 0` the other two are forced to zero, so "no step" is a
1179        // single unambiguous pattern rather than stale numbers the policy might
1180        // still act on.
1181        let cue = state.step_cue;
1182        let live = cue.valid > 0.5;
1183        put(obs, &mut o, if live { cue.distance.clamp(-0.5, 1.5) } else { 0.0 });
1184        put(obs, &mut o, if live { cue.height.clamp(-0.4, 0.4) } else { 0.0 });
1185        put(obs, &mut o, if live { cue.edge_sin } else { 0.0 });
1186        put(obs, &mut o, if live { cue.edge_cos } else { 0.0 });
1187        put(obs, &mut o, if live { 1.0 } else { 0.0 });
1188        // Upper-body block LAST (slots 53..79), so every earlier slot keeps its
1189        // v22-v28 meaning — mirror transform / sim2sim / controller all index
1190        // by position. No noise: targets are the controller's own commands.
1191        for i in 0..NUM_HELD_OBS {
1192            put(obs, &mut o, state.held_pos[i]);
1193        }
1194        for i in 0..NUM_HELD_OBS {
1195            put(obs, &mut o, state.held_vel[i]);
1196        }
1197        debug_assert_eq!(o, OBS_DIM);
1198    }

1200    /// Assemble the privileged critic observation: the policy obs followed by the
1201    /// (un-noised, normally unobservable) base linear & angular velocity.
1202    pub fn observe_critic(&self, state: &RobotState, cmd: &VelocityCommand, obs: &mut [f32]) {
1203        debug_assert_eq!(obs.len(), CRITIC_OBS_DIM);
1204        self.observe(state, cmd, &mut obs[..OBS_DIM]);
1205        let v = self.base_lin_vel_body(&state.base);
1206        let w = self.base_ang_vel_body(&state.base);
1207        obs[OBS_DIM..OBS_DIM + 3].copy_from_slice(&v);
1208        obs[OBS_DIM + 3..OBS_DIM + 6].copy_from_slice(&w);
1209        // Clean cue (see CRITIC_OBS_DIM): from step_cue_clean, which the env
1210        // fills with the raw oracle BEFORE actor-side noise and dropout.
1211        let cc = state.step_cue_clean;
1212        let live = cc.valid > 0.5;
1213        obs[OBS_DIM + 6] = if live { cc.distance.clamp(-0.5, 1.5) } else { 0.0 };
1214        obs[OBS_DIM + 7] = if live { cc.height.clamp(-0.4, 0.4) } else { 0.0 };
1215        obs[OBS_DIM + 8] = if live { cc.edge_sin } else { 0.0 };
1216        obs[OBS_DIM + 9] = if live { cc.edge_cos } else { 0.0 };
1217        obs[OBS_DIM + 10] = if live { 1.0 } else { 0.0 };
1218    }

1220    /// Compute the per-term reward for one control step.
1221    pub fn reward(&self, state: &RobotState, cmd: &VelocityCommand) -> RewardBreakdown {
1222        let dt = self.control_dt();
1223        let v = self.base_lin_vel_body(&state.base);
1224        let w = self.base_ang_vel_body(&state.base);
1225        let grav = self.projected_gravity(&state.base);
1226
1227        // Tracking (exp kernels) + a LINEAR forward-progress term. The exp kernel
1228        // saturates to ~0 (and flat) when the robot is far below the commanded
1229        // speed, so a march-in-place policy sits in a dead zone with no gradient
1230        // pulling it forward (measured: track_lin_vel stuck ~0.014 for thousands
1231        // of iters while vx≈0.03). The linear term `w · clamp(v·ĉmd, 0, |cmd|)`
1232        // rewards forward velocity PROPORTIONALLY — a gradient at any speed, zero
1233        // for standing/backward — so any forward motion is rewarded and it can
1234        // climb out of the in-place optimum.
1235        let lin_err = (cmd.vx - v[FWD]).powi(2) + (cmd.vy - v[LAT]).powi(2);
1236        let cmd_speed = (cmd.vx * cmd.vx + cmd.vy * cmd.vy).sqrt();
1237        let v_along = if cmd_speed > 1e-6 {
1238            (v[FWD] * cmd.vx + v[LAT] * cmd.vy) / cmd_speed
1239        } else {
1240            0.0
1241        };
1242        let track_lin_vel =
1243            self.weights.track_lin_vel * (-lin_err / self.stds.lin_vel.powi(2)).exp() * dt
1244                + self.weights.forward_progress * v_along.clamp(0.0, cmd_speed) * dt;
1245
1246        let ang_err = (cmd.yaw_rate - w[UP]).powi(2);
1247        let track_ang_vel =
1248            self.weights.track_ang_vel * (-ang_err / self.stds.ang_vel.powi(2)).exp() * dt;
1249
1250        // STEP MANOEUVRE GATE. Climbing a step is flatly irrational under the
1251        // flat-ground reward: the base MUST rise relative to the surface it is
1252        // leaving (no choice of reference foot avoids that), and it MUST pitch
1253        // forward to get the swing leg up. Measured against a 0.20 m riser,
1254        // holding the normal kernels costs ~0.040/step of base_height plus
1255        // ~0.072/step of upright at a 15 deg lean -- together ~42% of all
1256        // positive reward, against a ~0.002 behaviour threshold. The policy
1257        // would correctly learn to refuse.
1258        //
1259        // So while a step is cued and close, widen both kernels rather than
1260        // moving their targets: the target is still where we want the robot to
1261        // END UP, we are only declining to charge it for the transient.
1262        //
1263        // PROGRESS-GATED, and this is load-bearing. The first version relaxed
1264        // on proximity alone, and the policy found the hack within 15k iters:
1265        // standing inside the relax zone earns near-max posture reward in ANY
1266        // pose, so it learned "cue valid -> stop". Measured on the step eval,
1267        // same checkpoint, same 10 cm step: cue ON froze at x=0.16 m while cue
1268        // OFF (blind) walked to 1.28 m -- the cue made behaviour WORSE, and
1269        // the refusal strengthened with training while turning and gait
1270        // atrophied alongside it (loitering generalises). Requiring real
1271        // motion toward the edge means a loiterer faces the normal kernels and
1272        // the zone pays nothing unless the manoeuvre is actually happening.
1273        // Threshold 0.1 m/s matches the standing predicate's scale.
1274        let toward_step =
1275            v[FWD] * state.step_cue.edge_cos + v[LAT] * state.step_cue.edge_sin;
1276        let stepping = state.step_cue.valid > 0.5
1277            && state.step_cue.distance.abs() < self.step_relax_dist
1278            && toward_step > 0.1;
1279        let (std_h, std_up) = if stepping {
1280            (self.step_std_base_h, self.step_std_upright)
1281        } else {
1282            (self.stds.base_height, self.stds.upright)
1283        };
1284
1285        // Upright: horizontal components of projected gravity → 0 when flat.
1286        let tilt_err = grav[FWD].powi(2) + grav[LAT].powi(2);
1287        let upright = self.weights.upright * (-tilt_err / std_up.powi(2)).exp() * dt;
1288
1289        // Base height: stand tall (exp kernel around the target) so the policy
1290        // can't trivially crouch to avoid falling. The target is
1291        // command-conditioned: standing may ask for a taller, straighter-legged
1292        // stance than the gait wants, which cuts the continuous knee holding
1293        // torque (measured 28 N-m at a 31 deg stand knee) without forcing the
1294        // gait itself higher. Same `cmd.speed() < 0.1` gate the gait clock,
1295        // stand_planted and single_support already switch on, so this adds no
1296        // new discontinuity -- it rides one that is already there.
1297        let h_target = if cmd.speed() < 0.1 {
1298            self.weights.base_height_target_stand
1299        } else {
1300            self.weights.base_height_target
1301        };
1302        let h_err = (state.base.height - h_target).powi(2);
1303        let base_height = self.weights.base_height * (-h_err / std_h.powi(2)).exp() * dt;
1304
1305        // Hip yaw/roll deviation penalty (reuses the `pose` slot — the WBC port
1306        // left the full-posture reward at weight 0). The LATERAL hip DOFs (hipz
1307        // yaw, hipx roll) should stay near neutral whether standing OR walking
1308        // straight; without a penalty the policy braces by jamming them to their
1309        // ±20° limits (limit-riding — a degenerate, non-transferring stance).
1310        // L2 penalty (negative weight), ALWAYS-on so it also keeps the gait from
1311        // splaying. Targets ONLY hipz/hipx, leaving the sagittal walking DOFs
1312        // (hipy/knee/ankley) free. `weights.pose` is the (negative) penalty gain.
1313        let standing = cmd.speed() < 0.1;
1314        let mut hip_dev2 = 0.0;
1315        for &i in &self.hip_yawroll_idx {
1316            hip_dev2 += (state.joint_pos[i] - self.robot.joints[i].default_pos).powi(2);
1317        }
1318        let pose = self.weights.pose * hip_dev2 * dt;
1319
1320        // Bilateral symmetry: sagittal joints (hipy/knee/ankley) mirror equal,
1321        // lateral joints (hipz/hipx/anklex) mirror opposite. Reward exp(-error).
1322        // Release the LATERAL half of the symmetry term in proportion to the
1323        // commanded turn: 1.0 going straight, 0.0 at |yaw_rate| >= the gate.
1324        // Off (gate 0) = historical behaviour, lateral at full weight always.
1325        let lateral_scale = if self.sym_yaw_gate > 0.0 {
1326            (1.0 - cmd.yaw_rate.abs() / self.sym_yaw_gate).clamp(0.0, 1.0)
1327        } else {
1328            1.0
1329        };
1330        let sym_err = self.symmetry_error(&state.joint_pos, lateral_scale);
1331        let bilateral_symmetry = self.weights.bilateral_symmetry * (-sym_err).exp() * dt;
1332
1333        // Penalties (negative weights).
1334        let mut da2 = 0.0;
1335        for i in 0..NUM_JOINTS {
1336            da2 += (state.last_action[i] - state.prev_action[i]).powi(2);
1337        }
1338        let action_rate = self.weights.action_rate * da2 * dt;
1339
1340        // Action second difference (tremor at the source): Σ(a − 2a′ + a″)².
1341        let mut dda2 = 0.0;
1342        for i in 0..NUM_JOINTS {
1343            let dd = state.last_action[i] - 2.0 * state.prev_action[i] + state.prev2_action[i];
1344            dda2 += dd * dd;
1345        }
1346        let action_rate_rate = self.weights.action_rate_rate * dda2 * dt;
1347
1348        // Touchdown impact (kinematic slam): an airborne foot still
1349        // descending faster than `touchdown_vz_ok` below the gate height.
1350        let mut slam = 0.0;
1351        for f in &state.feet {
1352            if !f.contact && f.height < self.weights.touchdown_vz_h {
1353                let ex = (-f.vz - self.weights.touchdown_vz_ok).max(0.0);
1354                slam += ex * ex;
1355            }
1356        }
1357        let touchdown_vz = self.weights.touchdown_vz * slam * dt;
1358
1359        let mut da2_hip = 0.0;
1360        for &i in &self.hip_yawroll_idx {
1361            da2_hip += (state.last_action[i] - state.prev_action[i]).powi(2);
1362        }
1363        let action_rate_hipz_hipx = self.weights.action_rate_hipz_hipx * da2_hip * dt;
1364
1365        let body_ang_vel = self.weights.body_ang_vel * (w[FWD].powi(2) + w[LAT].powi(2)) * dt;
1366        let lin_vel_z = self.weights.lin_vel_z * v[UP].powi(2) * dt;
1367
1368        // Soft joint-position-limit penalty (soft band at 90% of the hard limit).
1369        let mut lim_pen = 0.0;
1370        for i in 0..NUM_JOINTS {
1371            let (lo, hi) = self.robot.joints[i].pos_limit;
1372            let (lo, hi) = (lo * 0.9, hi * 0.9);
1373            let q = state.joint_pos[i];
1374            lim_pen += (q - hi).max(0.0) + (lo - q).max(0.0);
1375        }
1376        let dof_pos_limits = self.weights.dof_pos_limits * lim_pen * dt;
1377
1378        let mut jv2 = 0.0;
1379        for i in 0..NUM_JOINTS {
1380            jv2 += state.joint_vel[i].powi(2);
1381        }
1382        let dof_vel = self.weights.dof_vel * jv2 * dt;
1383
1384        // --- foot-contact shaped terms ---
1385        let moving = !standing;
1386        // Forward-progress gate for the stepping BONUSES (air_time, single-support
1387        // bonus). Without it the policy farms those bonuses by stepping IN PLACE
1388        // (v≈0) — it overcooked into marching, abandoning forward tracking.
1389        // progress = clamp((v·cmd)/|cmd|², 0, 1): 1 when the base moves at the
1390        // commanded velocity, 0 when stationary/backward. So a stepping bonus is
1391        // only paid when the steps actually carry the robot toward the command.
1392        let cmd_sp2 = cmd.vx * cmd.vx + cmd.vy * cmd.vy;
1393        let progress = if cmd_sp2 > 1e-6 {
1394            ((v[FWD] * cmd.vx + v[LAT] * cmd.vy) / cmd_sp2).clamp(0.0, 1.0)
1395        } else {
1396            0.0
1397        };
1398        // Air time: reward the completed swing duration at touchdown (capped), so
1399        // any reasonable step is encouraged — only when commanded to move. (The old
1400        // `air_time − 0.5` form was negative for sub-0.5 s steps, i.e. it *punished*
1401        // this small robot's normal-cadence stepping.)
1402        // Pay the completed swing duration ONLY at an ALTERNATING touchdown
1403        // (f.alt_step). This is the unfarmable core of the gait: a foot held up
1404        // forever never lands (no reward); hopping on one foot earns nothing on
1405        // the repeat; only L→R→L→R stepping pays. Capped at 0.4 s/step.
1406        let mut air = 0.0;
1407        for f in &state.feet {
1408            if f.alt_step {
1409                air += f.air_time.min(0.4);
1410            }
1411        }
1412        let air_time = if moving {
1413            self.weights.air_time * air * dt * progress
1414        } else {
1415            0.0
1416        };
1417
1418        // Flight penalty: both feet off the ground = hopping/bounding, not walking.
1419        let flight = if state.feet.iter().all(|f| !f.contact) {
1420            self.weights.flight * dt
1421        } else {
1422            0.0
1423        };
1424
1425        // Gait-phase shaping (while moving). A *bonus* for stepping (air_time) gives
1426        // no exploration pressure — you only collect it AFTER you already step — so
1427        // from a shuffle the policy never discovers the first step. And a settle
1428        // BONUS for double-support actively rewarded the shuffle (measured: v40 sat
1429        // in permanent double-support, air_time stuck at 0). The pressure must come
1430        // from making NOT-stepping costly. So this term PENALIZES both degenerate
1431        // modes and leaves only alternating stepping unpunished:
1432        //   contacts==2 (permanent double-support = slide-shuffle) → penalty,
1433        //   contacts==1 but the airborne foot is HELD (air_time > MAX_SWING, i.e. a
1434        //     one-foot statue — the other hack) → penalty,
1435        //   contacts==1 with an ACTIVE swing (air_time ≤ MAX_SWING) → 0 (allowed),
1436        //   contacts==0 (flight) → 0, handled by `flight`.
1437        // A brief double-support SETTLE between steps costs little (a few steps of
1438        // small penalty); only PERMANENT double- or single-support is expensive.
1439        // The reward for doing it right is the alternation-gated air_time above.
1440        let contacts = state.feet.iter().filter(|f| f.contact).count();
1441        let single_support = if moving {
1442            match contacts {
1443                2 => -self.weights.single_support * dt, // permanent double-support = shuffle
1444                1 => {
1445                    // One foot up: fine if it's an active swing, penalized if it's a
1446                    // held statue (foot airborne longer than a normal swing).
1447                    let held = state
1448                        .feet
1449                        .iter()
1450                        .any(|f| !f.contact && f.air_time > MAX_SWING_S);
1451                    if held {
1452                        -self.weights.single_support * dt
1453                    } else {
1454                        0.0
1455                    }
1456                }
1457                _ => 0.0, // flight: see `flight`
1458            }
1459        } else {
1460            // STANDING (command ~0): the inverse — reward BOTH feet planted,
1461            // penalize stepping. Without this the walking policy keeps lifting
1462            // feet / stamping in place at zero command (it drifts + fidgets,
1463            // since nothing rewarded standing still). Now "step when told to move,
1464            // plant when told to stand" is symmetric.
1465            match contacts {
1466                2 => self.weights.single_support * dt, // both feet planted = good
1467                1 => -self.weights.single_support * dt, // stepping while told to stand = bad
1468                _ => 0.0,
1469            }
1470        };
1471
1472        // Extra "balance, don't step" pressure at stand (NEGATIVE weight, 0 = off;
1473        // BIPED_STAND_PLANTED_W): per airborne foot per step while the command is
1474        // standing. Stacks on the binary standing branch of `single_support`
1475        // above. Sized so quiet ankle/hip balancing beats fidget-stepping under
1476        // small pushes, while a genuine protective step (a few penalized steps)
1477        // stays far cheaper than falling (termination) under big ones.
1478        let stand_planted = if standing {
1479            let airborne = state.feet.iter().filter(|f| !f.contact).count() as f32;
1480            self.weights.stand_planted * airborne * dt
1481        } else {
1482            0.0
1483        };
1484
1485        // Slip: penalize horizontal foot speed while the foot is in contact.
1486        let mut slip = 0.0;
1487        for f in &state.feet {
1488            if f.contact {
1489                slip += f.planar_speed.powi(2);
1490            }
1491        }
1492        let foot_slip = self.weights.foot_slip * slip * dt;
1493
1494        // Ground-reaction smoothness: squared excess |ΔF| (body weights per
1495        // control step) above the deadband, per foot. Slam touchdowns and the
1496        // standing load-dither tremor both live here; gait weight transfer
1497        // stays inside the deadband. See the `force_rate` weight doc.
1498        let mut frate = 0.0;
1499        for f in &state.feet {
1500            let ex = (f.force_rate - self.weights.force_rate_deadband).max(0.0);
1501            frate += ex * ex;
1502        }
1503        let force_rate = self.weights.force_rate * frate * dt;
1504
1505        // Clearance: POSITIVE, capped reward for lifting an ACTIVE SWING foot above
1506        // its resting height, saturating at foot_clearance_target. Gated three ways
1507        // so it can't be farmed by holding one foot in the air (which is exactly how
1508        // the ungated version got hacked into a one-foot statue — 0 transfer):
1509        //   (1) f.contact == false   — only a lifted foot,
1510        //   (2) f.air_time < 0.45 s   — only an ACTIVE swing, not a held statue: a
1511        //       foot raised longer than a normal swing stops earning, so to keep
1512        //       collecting it must touch down (resetting air_time) and re-swing,
1513        //   (3) moving                — never at zero command (no stamping in place).
1514        const FOOT_REST_H: f32 = 0.035;
1515        const MAX_SWING_S: f32 = 0.45;
1516        // REWARDING THE STEP. While a step-up is cued and close, raise the
1517        // clearance target to the riser plus a margin, so "enough lift" means
1518        // enough to actually clear THIS step rather than a fixed 3 cm. The
1519        // reward saturates at the target (lift.min(1.0)), so raising it is
1520        // exactly "you must lift higher here" and nothing else changes.
1521        //
1522        // This reuses the existing term ON PURPOSE. foot_clearance was dropped
1523        // once because a static foot-height reward got hacked into a one-foot
1524        // statue (foot held up to farm it; zero transfer, MuJoCo fell in
1525        // 0.66 s). The guards added in response -- swing-only, air_time <
1526        // 0.45 s so a held foot stops earning, moving-gated, capped -- are
1527        // right here and apply unchanged. A fresh "reward crossing a step"
1528        // term would have none of them.
1529        const STEP_CLEAR_MARGIN: f32 = 0.05;
1530        let clear_target = if stepping && state.step_cue.height > 0.0 {
1531            (state.step_cue.height + STEP_CLEAR_MARGIN)
1532                .max(self.weights.foot_clearance_target)
1533        } else {
1534            self.weights.foot_clearance_target
1535        };
1536        let mut foot_h = 0.0;
1537        for f in &state.feet {
1538            if !f.contact && f.air_time < MAX_SWING_S {
1539                let lift = (f.height - FOOT_REST_H).max(0.0) / clear_target;
1540                foot_h += lift.min(1.0);
1541            }
1542        }
1543        let foot_clearance = if moving {
1544            self.weights.foot_clearance * foot_h * dt
1545        } else {
1546            0.0
1547        };
1548
1549        // Flat foot: penalize the squared sole tilt of any foot in contact, so the
1550        // robot plants its whole sole rather than balancing on a toe/heel/edge.
1551        // UNGATED (AGILE feet_roll_l2 parity): penalize sole tilt on ALL feet,
1552        // not just loaded ones. The contact-gated form left swing-foot posture
1553        // free, and the learned policy exploited it (hard dorsiflexion — toes
1554        // pointing up through swing; functional-ish for toe-clearance but an
1555        // engine-flattered habit under box friction, and ugly).
1556        let mut tilt_sq = 0.0;
1557        for f in &state.feet {
1558            tilt_sq += f.tilt.powi(2);
1559        }
1560        let foot_orientation = self.weights.foot_orientation * tilt_sq * dt;
1561
1562        // WBC's `feet_yaw_mean_vs_base`: sum of squared yaw (in base frame) over
1563        // both feet — drives each foot to point in the base's forward direction.
1564        let mut yaw_sq = 0.0;
1565        for f in &state.feet {
1566            yaw_sq += f.yaw_rel_base.powi(2);
1567        }
1568        let feet_yaw_mean = self.weights.feet_yaw_mean * yaw_sq * dt;
1569
1570        // WBC's `feet_yaw_diff_l2`: squared wrapped yaw difference between the
1571        // two feet (splay / pigeon-toe). Base-relative yaws work here — the base
1572        // yaw cancels in the difference.
1573        let feet_yaw_diff = if NUM_FEET == 2 {
1574            let d = state.feet[1].yaw_rel_base - state.feet[0].yaw_rel_base;
1575            let d = (d + core::f32::consts::PI).rem_euclid(2.0 * core::f32::consts::PI)
1576                - core::f32::consts::PI;
1577            self.weights.feet_yaw_diff * d.powi(2) * dt
1578        } else {
1579            0.0
1580        };
1581
1582        // WBC's `feet_distance_from_ref` (lateral mode): penalise the absolute
1583        // deviation of the lateral stance width from `feet_distance_ref`. We
1584        // transform the foot-to-foot world XY difference into the base frame
1585        // using only its yaw component (base assumed near-upright).
1586        let feet_distance = if NUM_FEET == 2 {
1587            let dx = state.feet[0].pos_xy[0] - state.feet[1].pos_xy[0];
1588            let dy = state.feet[0].pos_xy[1] - state.feet[1].pos_xy[1];
1589            // Project (dx, dy) world into base frame using base yaw.
1590            let q = &state.base.orientation; // (x, y, z, w)
1591            let base_yaw =
1592                (2.0 * (q[3] * q[2] + q[0] * q[1])).atan2(1.0 - 2.0 * (q[1] * q[1] + q[2] * q[2]));
1593            let cy = base_yaw.cos();
1594            let sy = base_yaw.sin();
1595            // Inverse-yaw rotation: world → base.
1596            let lateral = -sy * dx + cy * dy;
1597            let err = lateral.abs() - self.weights.feet_distance_ref;
1598            // L1 error like WBC's default `norm="l1"`.
1599            self.weights.feet_distance * err.abs() * dt
1600        } else {
1601            0.0
1602        };
1603
1604        // Periodic gait clock (DENSE). Foot 0's cycle starts at `phase`, foot 1 is
1605        // offset half a cycle, so they alternate. Within a foot's cycle, the first
1606        // `gait_swing_ratio` is the SWING window (the foot should be airborne), the
1607        // rest is STANCE (it should be in contact). Each step, each foot earns the
1608        // weight if its actual contact matches its prescribed phase. This pays
1609        // every step (not just at touchdown), so the gradient pulls the foot up at
1610        // the right time even before a full step succeeds — the dense signal the
1611        // sparse air_time bonus lacked. Only while moving (no forced gait at stand).
1612        // Siekmann-style: each foot scores +1 when its contact MATCHES its phase
1613        // (airborne in swing / grounded in stance) and −1 when it MISMATCHES. The
1614        // −1 for contact-during-swing is the crucial part (my first version gave 0
1615        // there): it makes keeping a foot down during its swing window actively
1616        // COSTLY, so standing no longer farms the stance windows for free — the
1617        // only way to stop bleeding reward is to actually lift on schedule. The
1618        // −1 for airborne-during-stance also penalizes a held-up statue foot.
1619        let gait_clock = if moving {
1620            let sr = self.weights.gait_swing_ratio;
1621            let mut gc = 0.0;
1622            for (k, f) in state.feet.iter().enumerate() {
1623                let ph = (state.phase + 0.5 * k as f32).fract();
1624                let want_swing = ph < sr;
1625                let matched = if want_swing { !f.contact } else { f.contact };
1626                gc += if matched { 1.0 } else { -1.0 };
1627            }
1628            // PROGRESS-GATE the gait reward: on-schedule stepping only pays when the
1629            // steps actually carry the body toward the command. Without this the
1630            // policy farms gait_clock by marching IN PLACE (measured: v47 stepped
1631            // cleanly — 5 cm lifts, 8–9 touchdowns — but vx≈0.03 m/s). The gate
1632            // makes forward steps the only way to earn it (progress = (v·cmd)/|cmd|²).
1633            // The double-support penalty (single_support, ungated) still backstops
1634            // against simply standing, so it must step — now forward.
1635            self.weights.gait_clock * gc * dt * progress
1636        } else {
1637            0.0
1638        };
1639
1640        RewardBreakdown {
1641            track_lin_vel,
1642            track_ang_vel,
1643            upright,
1644            base_height,
1645            pose,
1646            bilateral_symmetry,
1647            action_rate,
1648            action_rate_hipz_hipx,
1649            body_ang_vel,
1650            lin_vel_z,
1651            dof_pos_limits,
1652            dof_vel,
1653            air_time,
1654            flight,
1655            single_support,
1656            stand_planted,
1657            foot_slip,
1658            force_rate,
1659            action_rate_rate,
1660            touchdown_vz,
1661            foot_clearance,
1662            foot_orientation,
1663            feet_yaw_mean,
1664            feet_yaw_diff,
1665            feet_distance,
1666            gait_clock,
1667        }
1668    }
1669
1670    /// Mirror error: pairs left/right joints via the spec's mirror permutation
1671    /// and accumulates the squared difference under the family's mirror sign
1672    /// (sagittal joints mirror equal, lateral joints mirror opposite).
1673    /// `lateral_scale` attenuates ONLY the mirror-opposite joints (hip_roll,
1674    /// hip_yaw, ankle_roll — `mirror_sign < 0`). Those are "symmetric" when
1675    /// `q_L = -q_R`, i.e. mirror images. Turning needs the opposite: both
1676    /// hip_yaws rotate the SAME way, so the error is `(q + q)^2 = 4q^2` — the
1677    /// worst case for that term. Measured on v26's weights, 0.2 rad of
1678    /// coordinated hip yaw costs ~0.005/step against a ~0.002 behaviour
1679    /// threshold, so a commanded turn is actively taxed for the one thing it
1680    /// must do. The sagittal terms (hip_pitch, knee, ankle_pitch) are what keep
1681    /// the gait even and are never attenuated.
1682    fn symmetry_error(&self, q: &[f32; NUM_JOINTS], lateral_scale: f32) -> f32 {
1683        let mut err = 0.0;
1684        for i in 0..NUM_JOINTS {
1685            let jr = self.robot.mirror[i];
1686            if jr <= i {
1687                continue; // count each L/R pair once
1688            }
1689            let e = (q[i] - self.robot.mirror_sign[i] * q[jr]).powi(2);
1690            err += if self.robot.mirror_sign[i] < 0.0 {
1691                lateral_scale * e
1692            } else {
1693                e
1694            };
1695        }
1696        err
1697    }

1699    /// Whether the episode should terminate from a fall: excessive tilt, sunk too
1700    /// low (the anti-reward-hack floor), or a non-finite base. The env adds the
1701    /// separate time-out termination at [`Self::max_steps`].
1702    pub fn fell_over(&self, base: &BaseState) -> bool {
1703        !base.height.is_finite()
1704            || base.height < self.min_base_height
1705            || self.upright_cos(base) < self.tilt_limit.cos()
1706    }
