1//! **Flat velocity tracking** for the LeRobot bipedal — the first milestone:
2//! reproduce, in Rust on nexus, the deployed
3//! `Mjlab-Velocity-Flat-LeRobot-Humanoid-no-arms` policy.
4//!
5//! The robot walks on flat ground tracking a commanded planar velocity
6//! `(vx, vy, yaw_rate)`. This file is the *task config* (Isaac Lab tier): the
7//! observation layout, the action→joint-target map, the reward terms with their
8//! weights, the command sampler, and the termination rule — ported from the
9//! mjlab config of that policy and AGILE's T1 velocity task.
10//!
11//! It is pure CPU code over [`RobotState`]; the env loop fills that struct from
12//! nexus readback (`dof_values`/`dof_state` + base pose/velocity) and applies the
13//! [`VelocityFlatTask::joint_targets`] output through the joint PD controllers.
14//!
15//! ## Frame convention (Z-up)
16//!
17//! The env runs Z-up, matching the MuJoCo model and the real robot: base axes
18//! **forward = +X, lateral = +Y, up = +Z**; yaw is rotation about +Z. (Verified
19//! against the spawned MJCF stance in `biped_mjcf`.)
20//!
21//! ## Reward terms
22//!
23//! Proprioceptive terms (velocity/yaw tracking, upright, posture, symmetry,
24//! action-rate, joint penalties) and the **foot-contact** terms (feet air-time,
25//! foot-slip, foot-clearance) are all live — the env fills [`FootObs`] from the
26//! simulator's contacts. A few minor deployed terms remain unimplemented
27//! (action-FFT smoothness band, angular-momentum, soft-landing) and
28//! self-collision is N/A here (only the feet carry colliders).
29

41/// Observation vector length (policy group): `last_action(12) + command(4) +
42/// joint_pos_rel(12) + joint_vel(12) + projected_gravity(3) + gait_phase(2)`.
43/// The trailing 2 are (sin 2πφ, cos 2πφ) of the gait clock so the policy can
44/// time its steps to the periodic gait reward.
45// `+ 3` at the end is the base ANGULAR VELOCITY (gyro). Added after v21: the
46// actor had no rotation sense at all — angular velocity was critic-only
47// privileged information — so yaw control was open-loop and the policy could
48// not cancel even its own heading drift (measured: yaw output scattered
49// positive regardless of commanded sign). Every deployed locomotion stack
50// feeds the gyro to the policy; it is free on hardware (IMU).
51// `+ 5` at the very end is the STEP CUE (slots 48-52): distance to the edge,
52// its signed height, the edge ORIENTATION as (sin, cos) in the body frame, and
53// a validity flag. Supplied on hardware by a head RealSense: a plane fit plus
54// edge extraction yields all three quantities directly, and unlike a foot
55// probe it gives the edge DIRECTION -- which is what lets the robot meet a
56// step at an angle rather than only head-on. Trained against a terrain oracle
57// with sensor-shaped noise (see `StepCue`).
58pub const OBS_DIM: usize =
59    NUM_JOINTS + 4 + NUM_JOINTS + NUM_JOINTS + 3 + 2 + 3 + 5;
60/// Action vector length: one position target per leg DOF.
61pub const ACTION_DIM: usize = NUM_JOINTS;
62/// Privileged (critic) observation length: policy obs plus base linear & angular
63/// velocity in the body frame. Foot/contact privileged terms are deferred.
64// `+ 5` is the CLEAN step cue: the critic always sees the true edge state,
65// un-noised and never dropped, even while the ACTOR's copy (slots 48..53 of
66// the policy obs) is heavily dropout-masked early in training. Asymmetric
67// actor-critic: the value function credits crossing correctly on steps the
68// actor could not see, so the gradient learns "crossing pays" from blind
69// practice -- the fix for the observed cue->caution trap, where a policy
70// that has not yet learned to climb treats the cue purely as a fall
71// predictor and stops.
72pub const CRITIC_OBS_DIM: usize = OBS_DIM + 3 + 3 + 5;

111/// Per-foot state needed by the contact-shaped rewards. The env fills this from
112/// the simulator's contacts; `air_time` is tracked across steps by the env.
113#[derive(Clone, Copy, Debug)]
114pub struct FootObs {
115    /// Foot is touching the ground this step.
116    pub contact: bool,
117    /// Touchdown this step (was airborne last step, now in contact).
118    pub first_contact: bool,
119    /// Seconds the foot has been airborne (0 while in contact).
120    pub air_time: f32,
121    /// Foot world height, m.
122    pub height: f32,
123    /// Foot horizontal speed, m/s (for slip / clearance shaping).
124    pub planar_speed: f32,
125    /// Sole tilt from horizontal, rad (0 = sole flat on the ground). Used by the
126    /// flat-foot reward so the robot plants its whole sole, not an edge/toe/heel.
127    pub tilt: f32,
128    /// Foot yaw RELATIVE to the base (rad; 0 = foot points the same direction as
129    /// base). Computed by the env as `atan2(y, x)` of `q_base⁻¹·q_foot · X̂`. Used
130    /// by `feet_yaw_mean`.
131    pub yaw_rel_base: f32,
132    /// Foot world horizontal position (m). The reward uses the difference between
133    /// the two feet's positions, transformed into the base frame, to compute the
134    /// lateral stance width.
135    pub pos_xy: [f32; 2],
136    /// Touchdown this step that ALTERNATED feet — `first_contact` AND the *other*
137    /// foot was the most recent to touch down (set by the env, which tracks the
138    /// last-touchdown foot per env). The swing/air-time reward keys off this so a
139    /// step only pays when feet alternate (L→R→L→R): a foot held permanently in
140    /// the air never touches down (no reward), and double-tapping the same foot
141    /// (hopping) earns nothing on the repeat. Forces a real alternating gait.
142    pub alt_step: bool,
143    /// Foot vertical velocity, m/s (world +Z; negative = descending). Env
144    /// finite-diff, 0 on the first step after reset. Drives the
145    /// `touchdown_vz` slam penalty — the KINEMATIC impact term (a slam is a
146    /// foot still descending fast near the ground; kinematics transfer
147    /// across engines far better than contact-sensor forces do).
148    pub vz: f32,
149    /// One-step change in this foot's sensed normal contact force, in BODY
150    /// WEIGHTS per control step (|F_t − F_{t−1}| / (m·g), ≥ 0). Filled by the
151    /// env from the contact-force sensor (BIPED_CONTACT_SENSE); 0 when force
152    /// sensing is off or on the first step after a reset. Drives the
153    /// `force_rate` ground-reaction-smoothness penalty: a hard touchdown is a
154    /// 1–2 BW jump in one step, and the standing tremor is a sustained
155    /// left/right load dither — both are pure force-rate, while calm standing
156    /// and normal gait weight transfer (~0.06–0.12 BW/step) are ~free.
157    pub force_rate: f32,
158}

179/// What the head RealSense reports about the step ahead.
180///
181/// Extraction is a SCRIPTED perception step, not something the policy learns:
182/// a plane fit plus edge detection on the depth image yields distance, height
183/// and edge orientation directly. The policy's job is only to EXECUTE the step
184/// given those numbers -- which is why this is 5 floats into the existing MLP
185/// rather than a CNN on raw depth.
186///
187/// `valid = 0` must mean "no step information" and the policy must walk
188/// normally on it -- otherwise a dropped detection on hardware becomes a fall
189/// rather than a refusal.
190#[derive(Clone, Copy, Debug, Default)]
191pub struct StepCue {
192    /// Horizontal distance from the stance to the edge, m. Meaningless when
193    /// `valid == 0`.
194    pub distance: f32,
195    /// Signed height of the surface beyond the edge, m. Positive = step UP,
196    /// negative = step DOWN.
197    pub height: f32,
198    /// Edge normal direction in the BODY frame, as (sin, cos) of the angle
199    /// between the robot's heading and the edge normal. (0, 1) means the edge
200    /// is square-on. Split into sin/cos rather than a raw angle so it is
201    /// continuous across the +/-pi wrap, and so the mirror transform is a
202    /// clean sign flip on sin alone.
203    pub edge_sin: f32,
204    pub edge_cos: f32,
205    /// 1.0 when a detection succeeded, 0.0 otherwise (no step, or no reading).
206    pub valid: f32,
207}

209#[derive(Clone, Copy, Debug)]
210pub struct RobotState {
211    /// Base link state.
212    pub base: BaseState,
213    /// Joint positions, rad, in canonical joint order.
214    pub joint_pos: [f32; NUM_JOINTS],
215    /// Joint velocities, rad/s, in canonical joint order.
216    pub joint_vel: [f32; NUM_JOINTS],
217    /// Previous policy action (this step's `actions` observation).
218    pub last_action: [f32; NUM_JOINTS],
219    /// Action before that (for the action-rate-of-rate term).
220    pub prev_action: [f32; NUM_JOINTS],
221    /// Action before THAT — third point for the true second difference
222    /// (`action_rate_rate` = Σ(a − 2a' + a″)²), the action-side tremor
223    /// penalty: dither is action oscillation, so it's priced at the source
224    /// with no contact sensor in the loop (the sensor-side force_rate term
225    /// bred a straight-leg, transfer-breaking gait).
226    pub prev2_action: [f32; NUM_JOINTS],
227    /// Per-foot contact state (left, right).
228    pub feet: [FootObs; NUM_FEET],
229    /// Gait-clock phase ∈ [0,1), advanced by the env each control step. Drives
230    /// the periodic gait reward (foot 0 should swing near phase 0, foot 1 near
231    /// phase 0.5) and is fed to the policy as (sin 2πφ, cos 2πφ) so it can lock
232    /// its leg motion to the clock. The phase-clock reward provides a DENSE
233    /// per-step gradient toward an alternating swing/stance pattern — which the
234    /// sparse touchdown bonus (air_time) could not, since a step's payoff never
235    /// beat the fall risk (the shuffle stayed a stable local optimum).
236    pub phase: f32,
237    /// Latest step-cue report AS THE ACTOR SEES IT (noised, dropout-masked).
238    pub step_cue: StepCue,
239    /// The clean oracle cue, critic-only (asymmetric AC). Zero when unknown.
240    pub step_cue_clean: StepCue,
241}

260/// A commanded planar base velocity.
261#[derive(Clone, Copy, Debug, Default, PartialEq)]
262pub struct VelocityCommand {
263    /// Forward velocity, m/s.
264    pub vx: f32,
265    /// Lateral velocity, m/s.
266    pub vy: f32,
267    /// Yaw rate, rad/s.
268    pub yaw_rate: f32,
269}
270
271impl VelocityCommand {
272    /// The 4-channel command observation `[vx, vy, yaw_rate, aux]`. The 4th
273    /// channel is reserved (0.0) so the layout matches the deployed policy's
274    /// 4-wide `twist` command until its exact meaning is reconciled.
275    #[inline]
276    pub fn obs(&self) -> [f32; 4] {
277        [self.vx, self.vy, self.yaw_rate, 0.0]
278    }
279
280    /// Commanded planar speed (used for posture gating / zeroing).
281    #[inline]
282    pub fn speed(&self) -> f32 {
283        (self.vx * self.vx + self.vy * self.vy + self.yaw_rate * self.yaw_rate).sqrt()
284    }
285}

287/// Samples velocity commands like the mjlab/AGILE uniform velocity generator:
288/// uniform ranges, a fraction of standing (zero) commands, and periodic
289/// resampling. Ranges are the deployed policy's.
290#[derive(Clone, Debug)]
291pub struct CommandSampler {
292    /// `(min, max)` forward velocity, m/s.
293    pub lin_vel_x: (f32, f32),
294    /// `(min, max)` lateral velocity, m/s.
295    pub lin_vel_y: (f32, f32),
296    /// `(min, max)` yaw rate, rad/s.
297    pub ang_vel_z: (f32, f32),
298    /// Probability a resample yields a standing (all-zero) command.
299    pub standing_prob: f32,
300    /// `(min, max)` resample interval, seconds.
301    pub resample_s: (f32, f32),
302}

304/// Parse an env var holding a `"lo,hi"` range, e.g. `BIPED_YAW="-0.5,0.5"`.
305fn range_env(var: &str, default: (f32, f32)) -> (f32, f32) {
306    std::env::var(var)
307        .ok()
308        .and_then(|s| {
309            let p: Vec<f32> = s.split(',').filter_map(|x| x.trim().parse().ok()).collect();
310            (p.len() == 2).then(|| (p[0], p[1]))
311        })
312        .unwrap_or(default)
313}

315impl Default for CommandSampler {
316    fn default() -> Self {
317        // From the deployed Mjlab-Velocity-Flat-LeRobot config.
318        Self {
319            // Reachable at our budget: 0.5 m/s is achievable, 0.8 is not. With an
320            // unreachable max command the curriculum forces the policy into a
321            // regime where tracking reward is uniformly tiny → it gives up.
322            // Override per-axis with BIPED_VX / BIPED_VY / BIPED_YAW ("lo,hi").
323            lin_vel_x: range_env("BIPED_VX", (-0.8, 0.8)),
324            lin_vel_y: range_env("BIPED_VY", (-0.3, 0.3)),
325            // Yaw was ±0.2 through v21 — 5× narrower than WBC-AGILE T1's ±1.0,
326            // and too narrow to learn from: at |yaw| ≤ 0.2 the exp tracking
327            // kernel is nearly satisfied by NOT turning, so `track_ang_vel`
328            // earned only 0.006/step (13% of linear tracking) and v21 turned
329            // the WRONG WAY on a commanded ±0.2 (measured +0.03 / +0.02 rad/s
330            // for ±0.5, −0.05 for +0.2). Raising the weight 5→8 had already
331            // failed to fix it — the problem is the command range, not the
332            // price. ±0.6 gives the kernel something to discriminate while
333            // staying inside what the 12-DOF platform can turn.
334            // NOTE evaluations: ±0.5 was OUTSIDE the old training range, so
335            // every pre-v22 yaw probe at 0.5 was measuring extrapolation.
336            ang_vel_z: range_env("BIPED_YAW", (-0.6, 0.6)),
337            // Fraction of command resamples that are a pure STAND (zero). Raising
338            // it (BIPED_STAND_PROB) makes the robot stop more often → trains
339            // explicit walk→stand→walk (go-stop-go) transitions and gives frequent
340            // quasi-static "stabilize" checkpoints (helps the deliberate gait +
341            // transfer). Resample interval (BIPED_RESAMPLE_S, "lo,hi" seconds);
342            // shorter = more frequent transitions.
343            standing_prob: std::env::var("BIPED_STAND_PROB")
344                .ok()
345                .and_then(|s| s.parse().ok())
346                .unwrap_or(0.1),
347            resample_s: std::env::var("BIPED_RESAMPLE_S")
348                .ok()
349                .and_then(|s| {
350                    let p: Vec<f32> = s.split(',').filter_map(|x| x.parse().ok()).collect();
351                    if p.len() == 2 {
352                        Some((p[0], p[1]))
353                    } else {
354                        None
355                    }
356                })
357                .unwrap_or((3.0, 8.0)),
358        }
359    }
360}

362impl CommandSampler {
363    /// Draw a fresh command.
364    pub fn sample(&self, rng: &mut Lcg) -> VelocityCommand {
365        if rng.chance(self.standing_prob) {
366            return VelocityCommand::default();
367        }
368        let mut cmd = VelocityCommand {
369            vx: rng.range(self.lin_vel_x.0, self.lin_vel_x.1),
370            vy: rng.range(self.lin_vel_y.0, self.lin_vel_y.1),
371            yaw_rate: rng.range(self.ang_vel_z.0, self.ang_vel_z.1),
372        };
373        // Low-speed mass (BIPED_SLOW_PROB, default 0.25): uniform range
374        // sampling puts almost no probability on SLOW commands relative to
375        // the reward's sharp kernel, and the terrain curriculum pays for
376        // travel — the 30k-iter policy learned exactly two speeds (0 and
377        // ~±1 m/s), saturating every magnitude in between. Slow draws are
378        // rescaled onto a speed in [0.12, 0.3]: the quasi-static regime where
379        // single-support balance is hardest (and sim2sim falls live), kept
380        // strictly above the 0.1 standing threshold so the gait clock runs.
381        let slow_prob: f32 = std::env::var("BIPED_SLOW_PROB")
382            .ok()
383            .and_then(|s| s.parse().ok())
384            .unwrap_or(0.5);
385        // Arc bias (BIPED_ARC_PROB, default 0.25): with the yaw range widened
386        // to +/-0.6, independent uniform draws still put almost no mass on
387        // CURVED walking -- measured only ~5% of moving commands were strong
388        // arcs (|yaw|>=0.15 with |vx|>=0.3). Explicitly pair a real forward
389        // speed with a real yaw rate so turning-while-walking is in the data
390        // at all, not just turning-in-place.
391        let arc_prob: f32 = std::env::var("BIPED_ARC_PROB")
392            .ok()
393            .and_then(|s| s.parse().ok())
394            .unwrap_or(0.25);
395        if rng.chance(arc_prob) {
396            let sx = if rng.chance(0.5) { 1.0 } else { -1.0 };
397            let sy = if rng.chance(0.5) { 1.0 } else { -1.0 };
398            cmd.vx = sx * rng.range(0.25, self.lin_vel_x.1.abs().max(0.25));
399            cmd.yaw_rate = sy * rng.range(0.2, self.ang_vel_z.1.abs().max(0.2));
400            cmd.vy = 0.0;
401            return cmd;
402        }
403        if rng.chance(slow_prob) {
404            let target = rng.range(0.12, 0.3);
405            let speed = cmd.speed();
406            if speed > 1e-6 {
407                let k = target / speed;
408                cmd.vx *= k;
409                cmd.vy *= k;
410                cmd.yaw_rate *= k;
411            }
412        }
413        // A draw below the 0.1 standing threshold is contradictory: the gait
414        // clock freezes and stand_planted engages while tracking still asks
415        // for motion. Snap it to a true stand.
416        if cmd.speed() < 0.1 {
417            return VelocityCommand::default();
418        }
419        cmd
420    }
421
422    /// Draw a resample interval in control steps, given the control dt.
423    pub fn resample_steps(&self, rng: &mut Lcg, control_dt: f32) -> u32 {
424        (rng.range(self.resample_s.0, self.resample_s.1) / control_dt).round() as u32
425    }
426}

428/// Reward term weights (per-second; the task scales by the control dt). Defaults
429/// are the deployed policy's. `deferred_*` weights are recorded for parity but
430/// their terms aren't summed yet (they need contact readback).
431#[derive(Clone, Copy, Debug)]
432pub struct RewardWeights {
433    /// Linear-velocity tracking (exp kernel), `std` below.
434    pub track_lin_vel: f32,
435    /// Linear forward-progress reward: `w · clamp(v·ĉmd, 0, |cmd|)`. A non-saturating
436    /// gradient toward the commanded direction (breaks the march-in-place dead zone
437    /// where the exp tracking kernel is flat). Folded into the `track_lin_vel` term.
438    pub forward_progress: f32,
439    /// Angular (yaw) velocity tracking (exp kernel).
440    pub track_ang_vel: f32,
441    /// Upright / flat-orientation (exp kernel on tilt).
442    pub upright: f32,
443    /// Base-height tracking (exp kernel) — keeps the robot standing tall instead
444    /// of crouching to trivially avoid falling.
445    pub base_height: f32,
446    /// Target base (torso) height, m (for `base_height`) while MOVING.
447    pub base_height_target: f32,
448    /// Target base height, m, while STANDING (`cmd.speed() < 0.1`, the same gate
449    /// the gait clock freezes on). Defaults to `base_height_target`, so the
450    /// split is inert until `BIPED_BASE_HEIGHT_STAND` is set.
451    ///
452    /// Standing tall is nearly free in height but expensive in knee angle:
453    /// measured on this robot, height = 0.580*cos(knee/2) + 0.259, so the leg
454    /// ceiling is 0.839 m at knee 0 and the curve goes FLAT as it straightens
455    /// (15 deg -> 0 deg of knee buys only 5 mm). Two consequences:
456    ///   * a target ABOVE ~0.839 is unreachable without hyperextending into the
457    ///     -0.087 rad knee stop. That is what v22 did at 0.841 (locked at -4 deg,
458    ///     60% of frames on the stop, CoT 1.00) -- do not set one.
459    ///   * above ~0.837 the gradient falls under 0.5 mm/deg, so the only way to
460    ///     chase the last millimetres is to ride the stop.
461    /// 0.835 -> ~13.6 deg knee with 18.6 deg of stop margin, 4 mm under the
462    /// ceiling: reachable at a legal knee angle, unlike v22's target.
463    pub base_height_target_stand: f32,
464    /// Hip yaw/roll deviation penalty gain (NEGATIVE). L2 penalty on hipz+hipx
465    /// deviation from default, always-on — stops the policy from limit-riding the
466    /// lateral hips into a splayed brace. (Was an unused full-posture reward.)
467    pub pose: f32,
468    /// Left/right symmetry (exp kernel on mirror error).
469    pub bilateral_symmetry: f32,
470    /// L2 penalty on action change.
471    pub action_rate: f32,
472    /// L2 penalty on action change for the hip yaw/roll DOFs only.
473    pub action_rate_hipz_hipx: f32,
474    /// L2 penalty on base roll/pitch angular velocity.
475    pub body_ang_vel: f32,
476    /// L2 penalty on vertical base velocity.
477    pub lin_vel_z: f32,
478    /// Soft joint-position-limit penalty.
479    pub dof_pos_limits: f32,
480    /// L2 penalty on joint velocity.
481    pub dof_vel: f32,
482    /// One-shot penalty applied by the env on a non-timeout termination.
483    pub termination: f32,
484
485    // --- foot-contact shaped (need per-foot contact from the sim) ---
486    /// Feet air-time bonus on touchdown (shapes a stepping gait).
487    pub air_time: f32,
488    /// Penalty applied every step BOTH feet are off the ground. Forces a walking
489    /// gait (always ≥1 foot planted) instead of hopping/bounding.
490    pub flight: f32,
491    /// Bonus applied (while moving) every step EXACTLY ONE foot is on the ground.
492    /// Single-support is the defining phase of walking — rewarding it directly
493    /// makes stepping beat both standing (double-support) and hopping (flight).
494    pub single_support: f32,
495    /// Penalty (per airborne foot, per step) while the command is STANDING.
496    /// Makes the policy absorb small pushes with ankle/hip torque (feet
497    /// planted, CoM shifted) instead of dance-stepping
498    /// in place. MODERATE by design: for a big shove a protective step (brief
499    /// penalty) must stay cheaper than falling (termination), mirroring the
500    /// human ankle→hip→step strategy ladder. 0 = off.
501    pub stand_planted: f32,
502    /// Foot-slip penalty (horizontal foot speed while in contact).
503    pub foot_slip: f32,
504    /// Action second-difference penalty (NEGATIVE): Σ(a − 2a′ + a″)². The
505    /// ACTION-side tremor term — high-frequency dither is literally an
506    /// oscillating action, so this prices it at the policy's output with no
507    /// engine-specific signal in the loop. Complements (does not stack with)
508    /// `action_rate`, which only prices speed of change, not oscillation:
509    /// a smooth fast ramp scores high action_rate but ~0 here. 0 = off.
510    pub action_rate_rate: f32,
511    /// Touchdown-impact penalty (NEGATIVE): per airborne foot below
512    /// `touchdown_vz_h` (m), squared excess descent speed beyond
513    /// `touchdown_vz_ok` (m/s). Kinematic slam term: a soft landing decel-
514    /// erates BEFORE the ground, a slam is still fast at 5 cm. 0 = off.
515    pub touchdown_vz: f32,
516    /// Allowed descent speed at the gate height (m/s, default 0.3).
517    pub touchdown_vz_ok: f32,
518    /// Gate height above local ground (m, default 0.10). NOTE this compares
519    /// against `FootObs.height`, which is the foot link ORIGIN — ~0.035 m
520    /// above the sole even when planted (FOOT_REST_H). The first default
521    /// (0.06) left a ~2 cm trigger window that contact sensing pre-empted:
522    /// the term logged exactly 0 for 100 iters of newborn flailing. 0.10 =
523    /// sole ~6.5 cm up, a real approach window.
524    pub touchdown_vz_h: f32,
525    /// Ground-reaction smoothness penalty (NEGATIVE): per foot, the one-step
526    /// sensed-force change above `force_rate_deadband` (both in body weights
527    /// per control step), squared. Prices the two behaviours v26 shipped with:
528    /// foot-slam touchdowns (measured 0.9 BW mean / 2.1 BW peak first-contact
529    /// jumps in MuJoCo) and the standing tremor (left/right load share
530    /// dithering 0→1 at ~18 Hz with both feet planted — invisible in base
531    /// motion, but exactly a sustained |ΔF|). Deadband keeps normal gait
532    /// weight transfer (~0.06–0.12 BW/step) free, so walking itself is not
533    /// taxed. 0 = off. Needs BIPED_CONTACT_SENSE (no sensor → term is 0).
534    pub force_rate: f32,
535    /// Deadband for `force_rate`, body weights per control step (default 0.15).
536    pub force_rate_deadband: f32,
537    /// Foot-clearance penalty (swing-foot height vs target).
538    pub foot_clearance: f32,
539    /// Target swing-foot clearance height, m (for `foot_clearance`).
540    pub foot_clearance_target: f32,
541    /// Flat-foot penalty: penalizes sole tilt (rad²) of a foot IN CONTACT, so the
542    /// robot plants its whole sole flat instead of balancing on a toe/heel/edge.
543    pub foot_orientation: f32,
544    /// WBC's `feet_yaw_mean_vs_base`: penalty on each foot's yaw (in base frame),
545    /// summed over both feet. Strong because un-shaped foot yaw is the dominant
546    /// posture artefact for under-constrained humanoid RL.
547    pub feet_yaw_mean: f32,
548    /// WBC's `feet_yaw_diff_l2`: penalty on the squared wrapped yaw difference
549    /// between the two feet (splayed/pigeon-toed stance). AGILE G1 weight −0.1,
550    /// lerobot −0.02.
551    pub feet_yaw_diff: f32,
552    /// WBC's `feet_distance_from_ref` (lateral mode): penalises deviation of the
553    /// lateral (body-Y) foot separation from `feet_distance_ref`.
554    pub feet_distance: f32,
555    /// Reference lateral foot separation, m (for `feet_distance`).
556    pub feet_distance_ref: f32,
557    /// Periodic gait-clock reward (dense). Each step, each foot earns up to this
558    /// weight for matching its prescribed phase: airborne during its swing window,
559    /// in contact during its stance window. Provides the dense gradient toward an
560    /// alternating gait that the sparse touchdown bonus could not.
561    pub gait_clock: f32,
562    /// Fraction of each foot's gait cycle spent in swing (rest is stance). With
563    /// the feet offset by half a cycle, `1 - 2·swing_ratio` of the cycle is
564    /// double-support — the built-in "both feet down in the middle".
565    pub gait_swing_ratio: f32,
566}

921    /// Build the task for an explicit robot spec.
922    pub fn for_robot(robot: RobotSpec) -> Self {
923        // The hip yaw/roll DOFs for the targeted action-rate penalty (these
924        // lateral-hip joints are the jittery ones) come from the spec.
925        let hip_yawroll_idx = robot.hip_yawroll;
926        // Reward-weight overrides for fast retuning without a rebuild. The
927        // stand-still local optimum (policy collects upright + base_height +
928        // free track_ang at zero command, ignores the velocity command) is the
929        // walking blocker, so the key dials are the velocity-tracking weight vs
930        // the standing magnets (upright / base_height). Set e.g.
931        // `BIPED_W_TRACK_LIN=10 BIPED_W_UPRIGHT=3 BIPED_W_BASE_H=1.5` at launch.
932        // BIPED_AGILE_REWARDS=1: WBC-AGILE's exact G1 term set — no stepping
933        // rewards, no extra stand income, AGILE kernel widths, AGILE's 0.72 m
934        // bent-knee height target (NOT the per-robot straight-leg default).
935        // Pair with BIPED_POWER_W=0 (AGILE has no power term).
936        let agile_rewards = std::env::var("BIPED_AGILE_REWARDS").is_ok_and(|v| v == "1");
937        if agile_rewards {
938            println!(
939                "AGILE reward parity ENABLED: WBC-AGILE G1 term set (no stepping rewards), \
940                 stds lin/ang 0.2, height target 0.72"
941            );
942        }
943        let mut weights = if agile_rewards {
944            RewardWeights::agile()
945        } else {
946            RewardWeights::default()
947        };
948        // The base-height target is per-robot (lerobot trunk 0.72 m, G1 pelvis
949        // 0.78 m, H2 Plus pelvis 1.03 m); the RewardWeights default keeps the
950        // lerobot value for struct-literal users.
951        if !agile_rewards {
952            weights.base_height_target = robot.base_height;
953        }
954        let env_f32 = |k: &str| std::env::var(k).ok().and_then(|s| s.parse::<f32>().ok());
955        if let Some(v) = env_f32("BIPED_W_TRACK_LIN") {
956            weights.track_lin_vel = v;
957        }
958        if let Some(v) = env_f32("BIPED_W_TRACK_ANG") {
959            weights.track_ang_vel = v;
960        }
961        if let Some(v) = env_f32("BIPED_W_UPRIGHT") {
962            weights.upright = v;
963        }
964        if let Some(v) = env_f32("BIPED_W_BASE_H") {
965            weights.base_height = v;
966        }
967        // Target height for the base_height kernel. AGILE's 0.72 is a
968        // bent-knee stance; measured v21 sits 4-9 cm BELOW even that
969        // (0.63-0.68 m vs 0.79 natural) because crouching buys balance
970        // stability and the wide sigma=0.1 kernel makes the undershoot
971        // cheap. 0.75 is the recommended first step up; 0.78+ risks the
972        // straight-knee singularity where the leg loses vertical control
973        // authority.
974        // NOTE: BIPED_BASE_HEIGHT sets BOTH targets, so the historical
975        // single-knob behaviour is preserved exactly. BIPED_BASE_HEIGHT_STAND
976        // is applied AFTER it and overrides the standing one only -- order
977        // matters, do not reorder these two blocks.
978        if let Some(v) = env_f32("BIPED_BASE_HEIGHT") {
979            weights.base_height_target = v;
980            weights.base_height_target_stand = v;
981        }
982        // Command-conditioned standing height. The policy already prefers a
983        // taller stance than its gait (v24 measured 0.816 standing vs 0.807
984        // walking), so this codifies an existing preference rather than
985        // fighting one. See the field docs for the knee-angle geometry and why
986        // anything above ~0.837 rides the knee stop.
987        weights.base_height_target_stand =
988            env_f32("BIPED_BASE_HEIGHT_STAND").unwrap_or(weights.base_height_target + 0.01);
989        // AGILE-alignment override: WBC has NO air-time reward — its gait
990        // economy comes from torque/energy regularizers. Paying completed
991        // swing DURATION (capped 0.4s ≈ our natural swing) selects for
992        // maximal, exaggerated swings once a gait exists. 0 = AGILE parity.
993        if let Some(v) = env_f32("BIPED_W_AIR_TIME") {
994            weights.air_time = v;
995        }
996        let mut stds = if agile_rewards {
997            RewardStds::agile()
998        } else {
999            RewardStds::default()
1000        };
1001        if let Some(v) = env_f32("BIPED_STD_LIN") {
1002            stds.lin_vel = v;
1003        }
1004        // Width of the height kernel (BIPED_STD_BASE_H, metres). The default
1005        // 0.1 is wide enough that a 4 cm undershoot still collects 85% of the
1006        // reward, which is why v21 sat 4 cm below its own target and stayed
1007        // there. Tightening to ~0.05 makes a crouch cost the height reward
1008        // outright -- the direct way to price posture, instead of taxing knee
1009        // torque and hoping the posture follows.
1010        stds.base_height = env_f32("BIPED_STD_BASE_H").unwrap_or(0.05);
1011        // Width of the ANGULAR tracking kernel. The default 0.1 is far too
1012        // narrow for the +/-0.6 command range: a policy sitting at the measured
1013        // 0.06 rad/s scores exp(-(0.4-0.06)^2/0.1^2) = 1e-5 on a 0.4 command,
1014        // i.e. NO gradient to climb. Measured on v24 at iter 32-42k, which
1015        // never learned to turn despite the gyro, the widened yaw range and 25%
1016        // arc sampling -- the arcs sample yaw in [0.2, 0.6], of which only the
1017        // 0.2 edge pays anything at all (14%; 0.35 pays 0.02%).
1018        //
1019        // v22 DID turn (+0.38) because it happened to land inside the basin,
1020        // after which a 0.4 command scores 96% and self-reinforces. That is
1021        // luck, not a gradient. 0.3 makes a 0.4 command pay 28% from a standing
1022        // start, so there is a slope the whole way in.
1023        stds.ang_vel = env_f32("BIPED_STD_ANG").unwrap_or(0.3);
1024        // Action-rate penalty gain (NEGATIVE). Exposed because it is denominated
1025        // in ACTION units, not radians: it charges (delta action)^2, so halving
1026        // BIPED_ACTION_SCALE makes the same PHYSICAL motion cost 4x more here.
1027        // Anyone running action_scale 0.25 must scale this by ~1/4 or the
1028        // penalty dominates and the policy simply stops moving.
1029        if let Some(v) = env_f32("BIPED_W_ACTION_RATE") {
1030            weights.action_rate = v;
1031        }
1032        Self {
1033            robot,
1034            weights,
1035            stds,
1036            sim_dt: 1.0 / 200.0,
1037            decimation: 4,
1038            episode_s: 20.0,
1039            tilt_limit: 70.0_f32.to_radians(),
1040            min_base_height: robot.min_base_height,
1041            hip_yawroll_idx,
1042            sym_yaw_gate: env_f32("BIPED_SYM_YAW_GATE").unwrap_or(0.0),
1043            step_relax_dist: env_f32("BIPED_STEP_RELAX_DIST").unwrap_or(0.6),
1044            step_std_base_h: env_f32("BIPED_STEP_STD_BASE_H").unwrap_or(0.15),
1045            step_std_upright: env_f32("BIPED_STEP_STD_UPRIGHT")
1046                .unwrap_or(25.0_f32.to_radians()),
1047        }
1048    }

1062    /// Map a policy action to per-joint PD position targets:
1063    /// `q_target = default_pos + action_scale · action`.
1064    pub fn joint_targets(&self, action: &[f32; NUM_JOINTS]) -> [f32; NUM_JOINTS] {
1065        std::array::from_fn(|i| {
1066            let j = self.robot.joints[i];
1067            // Clamp the PD target to the joint's physical limit. Unbounded targets
1068            // let the policy command far past the stops (measured: hipx target
1069            // ~1.5 rad vs a ±0.35 rad limit), so the PD slams the joint into its
1070            // limit at near-saturated torque every step. That "limit-riding" pose
1071            // is a degenerate local optimum: it wastes torque (critically on the
1072            // fragile ankle) and gives the policy a flat, zero-gradient region to
1073            // get stuck in — every trained policy collapsed to it. Clamping keeps
1074            // the commanded pose physical and the PD error (hence torque) bounded,
1075            // while still allowing each joint its FULL range (the action scale,
1076            // not ±1, sets how far |action| must go to reach the limit).
1077            let (lo, hi) = j.pos_limit;
1078            (j.default_pos + j.action_scale * action[i]).clamp(lo, hi)
1079        })
1080    }

1111    /// Assemble the 43-dim policy observation into `obs`.
1112    ///
1113    /// Layout: `[last_action(12), command(4), joint_pos_rel(12), joint_vel(12),
1114    /// projected_gravity(3), gait_clock(2), base_ang_vel(3)]`.
1115    /// `joint_pos_rel = q − default_pos`.
1116    pub fn observe(&self, state: &RobotState, cmd: &VelocityCommand, obs: &mut [f32]) {
1117        debug_assert_eq!(obs.len(), OBS_DIM);
1118        let mut o = 0;
1119        let put = |obs: &mut [f32], o: &mut usize, v: f32| {
1120            obs[*o] = v;
1121            *o += 1;
1122        };
1123        for i in 0..NUM_JOINTS {
1124            put(obs, &mut o, state.last_action[i]);
1125        }
1126        for c in cmd.obs() {
1127            put(obs, &mut o, c);
1128        }
1129        for i in 0..NUM_JOINTS {
1130            put(
1131                obs,
1132                &mut o,
1133                state.joint_pos[i] - self.robot.joints[i].default_pos,
1134            );
1135        }
1136        for i in 0..NUM_JOINTS {
1137            put(obs, &mut o, state.joint_vel[i]);
1138        }
1139        for g in self.projected_gravity(&state.base) {
1140            put(obs, &mut o, g);
1141        }
1142        // Gait clock as (sin, cos) so it's continuous across the 1→0 wrap.
1143        let ph = state.phase * std::f32::consts::TAU;
1144        put(obs, &mut o, ph.sin());
1145        put(obs, &mut o, ph.cos());
1146        // Base angular velocity (body frame). Kept LAST so the preceding 45
1147        // slots keep their v21 meaning — the mirror transform, the sim2sim
1148        // harnesses and the lerobot controller all index by position.
1149        for w in self.base_ang_vel_body(&state.base) {
1150            put(obs, &mut o, w);
1151        }
1152        // Step cue LAST, so slots 0-47 keep their v22-v27 meaning. Distance is
1153        // clipped: beyond ~1.5 m the exact value carries no useful information
1154        // and an unclipped range would waste normalizer resolution on it.
1155        // When `valid == 0` the other two are forced to zero, so "no step" is a
1156        // single unambiguous pattern rather than stale numbers the policy might
1157        // still act on.
1158        let cue = state.step_cue;
1159        let live = cue.valid > 0.5;
1160        put(obs, &mut o, if live { cue.distance.clamp(-0.5, 1.5) } else { 0.0 });
1161        put(obs, &mut o, if live { cue.height.clamp(-0.4, 0.4) } else { 0.0 });
1162        put(obs, &mut o, if live { cue.edge_sin } else { 0.0 });
1163        put(obs, &mut o, if live { cue.edge_cos } else { 0.0 });
1164        put(obs, &mut o, if live { 1.0 } else { 0.0 });
1165        debug_assert_eq!(o, OBS_DIM);
1166    }

1168    /// Assemble the privileged critic observation: the policy obs followed by the
1169    /// (un-noised, normally unobservable) base linear & angular velocity.
1170    pub fn observe_critic(&self, state: &RobotState, cmd: &VelocityCommand, obs: &mut [f32]) {
1171        debug_assert_eq!(obs.len(), CRITIC_OBS_DIM);
1172        self.observe(state, cmd, &mut obs[..OBS_DIM]);
1173        let v = self.base_lin_vel_body(&state.base);
1174        let w = self.base_ang_vel_body(&state.base);
1175        obs[OBS_DIM..OBS_DIM + 3].copy_from_slice(&v);
1176        obs[OBS_DIM + 3..OBS_DIM + 6].copy_from_slice(&w);
1177        // Clean cue (see CRITIC_OBS_DIM): from step_cue_clean, which the env
1178        // fills with the raw oracle BEFORE actor-side noise and dropout.
1179        let cc = state.step_cue_clean;
1180        let live = cc.valid > 0.5;
1181        obs[OBS_DIM + 6] = if live { cc.distance.clamp(-0.5, 1.5) } else { 0.0 };
1182        obs[OBS_DIM + 7] = if live { cc.height.clamp(-0.4, 0.4) } else { 0.0 };
1183        obs[OBS_DIM + 8] = if live { cc.edge_sin } else { 0.0 };
1184        obs[OBS_DIM + 9] = if live { cc.edge_cos } else { 0.0 };
1185        obs[OBS_DIM + 10] = if live { 1.0 } else { 0.0 };
1186    }

1188    /// Compute the per-term reward for one control step.
1189    pub fn reward(&self, state: &RobotState, cmd: &VelocityCommand) -> RewardBreakdown {
1190        let dt = self.control_dt();
1191        let v = self.base_lin_vel_body(&state.base);
1192        let w = self.base_ang_vel_body(&state.base);
1193        let grav = self.projected_gravity(&state.base);
1194
1195        // Tracking (exp kernels) + a LINEAR forward-progress term. The exp kernel
1196        // saturates to ~0 (and flat) when the robot is far below the commanded
1197        // speed, so a march-in-place policy sits in a dead zone with no gradient
1198        // pulling it forward (measured: track_lin_vel stuck ~0.014 for thousands
1199        // of iters while vx≈0.03). The linear term `w · clamp(v·ĉmd, 0, |cmd|)`
1200        // rewards forward velocity PROPORTIONALLY — a gradient at any speed, zero
1201        // for standing/backward — so any forward motion is rewarded and it can
1202        // climb out of the in-place optimum.
1203        let lin_err = (cmd.vx - v[FWD]).powi(2) + (cmd.vy - v[LAT]).powi(2);
1204        let cmd_speed = (cmd.vx * cmd.vx + cmd.vy * cmd.vy).sqrt();
1205        let v_along = if cmd_speed > 1e-6 {
1206            (v[FWD] * cmd.vx + v[LAT] * cmd.vy) / cmd_speed
1207        } else {
1208            0.0
1209        };
1210        let track_lin_vel =
1211            self.weights.track_lin_vel * (-lin_err / self.stds.lin_vel.powi(2)).exp() * dt
1212                + self.weights.forward_progress * v_along.clamp(0.0, cmd_speed) * dt;
1213
1214        let ang_err = (cmd.yaw_rate - w[UP]).powi(2);
1215        let track_ang_vel =
1216            self.weights.track_ang_vel * (-ang_err / self.stds.ang_vel.powi(2)).exp() * dt;
1217
1218        // STEP MANOEUVRE GATE. Climbing a step is flatly irrational under the
1219        // flat-ground reward: the base MUST rise relative to the surface it is
1220        // leaving (no choice of reference foot avoids that), and it MUST pitch
1221        // forward to get the swing leg up. Measured against a 0.20 m riser,
1222        // holding the normal kernels costs ~0.040/step of base_height plus
1223        // ~0.072/step of upright at a 15 deg lean -- together ~42% of all
1224        // positive reward, against a ~0.002 behaviour threshold. The policy
1225        // would correctly learn to refuse.
1226        //
1227        // So while a step is cued and close, widen both kernels rather than
1228        // moving their targets: the target is still where we want the robot to
1229        // END UP, we are only declining to charge it for the transient.
1230        //
1231        // PROGRESS-GATED, and this is load-bearing. The first version relaxed
1232        // on proximity alone, and the policy found the hack within 15k iters:
1233        // standing inside the relax zone earns near-max posture reward in ANY
1234        // pose, so it learned "cue valid -> stop". Measured on the step eval,
1235        // same checkpoint, same 10 cm step: cue ON froze at x=0.16 m while cue
1236        // OFF (blind) walked to 1.28 m -- the cue made behaviour WORSE, and
1237        // the refusal strengthened with training while turning and gait
1238        // atrophied alongside it (loitering generalises). Requiring real
1239        // motion toward the edge means a loiterer faces the normal kernels and
1240        // the zone pays nothing unless the manoeuvre is actually happening.
1241        // Threshold 0.1 m/s matches the standing predicate's scale.
1242        let toward_step =
1243            v[FWD] * state.step_cue.edge_cos + v[LAT] * state.step_cue.edge_sin;
1244        let stepping = state.step_cue.valid > 0.5
1245            && state.step_cue.distance.abs() < self.step_relax_dist
1246            && toward_step > 0.1;
1247        let (std_h, std_up) = if stepping {
1248            (self.step_std_base_h, self.step_std_upright)
1249        } else {
1250            (self.stds.base_height, self.stds.upright)
1251        };
1252
1253        // Upright: horizontal components of projected gravity → 0 when flat.
1254        let tilt_err = grav[FWD].powi(2) + grav[LAT].powi(2);
1255        let upright = self.weights.upright * (-tilt_err / std_up.powi(2)).exp() * dt;
1256
1257        // Base height: stand tall (exp kernel around the target) so the policy
1258        // can't trivially crouch to avoid falling. The target is
1259        // command-conditioned: standing may ask for a taller, straighter-legged
1260        // stance than the gait wants, which cuts the continuous knee holding
1261        // torque (measured 28 N-m at a 31 deg stand knee) without forcing the
1262        // gait itself higher. Same `cmd.speed() < 0.1` gate the gait clock,
1263        // stand_planted and single_support already switch on, so this adds no
1264        // new discontinuity -- it rides one that is already there.
1265        let h_target = if cmd.speed() < 0.1 {
1266            self.weights.base_height_target_stand
1267        } else {
1268            self.weights.base_height_target
1269        };
1270        let h_err = (state.base.height - h_target).powi(2);
1271        let base_height = self.weights.base_height * (-h_err / std_h.powi(2)).exp() * dt;
1272
1273        // Hip yaw/roll deviation penalty (reuses the `pose` slot — the WBC port
1274        // left the full-posture reward at weight 0). The LATERAL hip DOFs (hipz
1275        // yaw, hipx roll) should stay near neutral whether standing OR walking
1276        // straight; without a penalty the policy braces by jamming them to their
1277        // ±20° limits (limit-riding — a degenerate, non-transferring stance).
1278        // L2 penalty (negative weight), ALWAYS-on so it also keeps the gait from
1279        // splaying. Targets ONLY hipz/hipx, leaving the sagittal walking DOFs
1280        // (hipy/knee/ankley) free. `weights.pose` is the (negative) penalty gain.
1281        let standing = cmd.speed() < 0.1;
1282        let mut hip_dev2 = 0.0;
1283        for &i in &self.hip_yawroll_idx {
1284            hip_dev2 += (state.joint_pos[i] - self.robot.joints[i].default_pos).powi(2);
1285        }
1286        let pose = self.weights.pose * hip_dev2 * dt;
1287
1288        // Bilateral symmetry: sagittal joints (hipy/knee/ankley) mirror equal,
1289        // lateral joints (hipz/hipx/anklex) mirror opposite. Reward exp(-error).
1290        // Release the LATERAL half of the symmetry term in proportion to the
1291        // commanded turn: 1.0 going straight, 0.0 at |yaw_rate| >= the gate.
1292        // Off (gate 0) = historical behaviour, lateral at full weight always.
1293        let lateral_scale = if self.sym_yaw_gate > 0.0 {
1294            (1.0 - cmd.yaw_rate.abs() / self.sym_yaw_gate).clamp(0.0, 1.0)
1295        } else {
1296            1.0
1297        };
1298        let sym_err = self.symmetry_error(&state.joint_pos, lateral_scale);
1299        let bilateral_symmetry = self.weights.bilateral_symmetry * (-sym_err).exp() * dt;
1300
1301        // Penalties (negative weights).
1302        let mut da2 = 0.0;
1303        for i in 0..NUM_JOINTS {
1304            da2 += (state.last_action[i] - state.prev_action[i]).powi(2);
1305        }
1306        let action_rate = self.weights.action_rate * da2 * dt;
1307
1308        // Action second difference (tremor at the source): Σ(a − 2a′ + a″)².
1309        let mut dda2 = 0.0;
1310        for i in 0..NUM_JOINTS {
1311            let dd = state.last_action[i] - 2.0 * state.prev_action[i] + state.prev2_action[i];
1312            dda2 += dd * dd;
1313        }
1314        let action_rate_rate = self.weights.action_rate_rate * dda2 * dt;
1315
1316        // Touchdown impact (kinematic slam): an airborne foot still
1317        // descending faster than `touchdown_vz_ok` below the gate height.
1318        let mut slam = 0.0;
1319        for f in &state.feet {
1320            if !f.contact && f.height < self.weights.touchdown_vz_h {
1321                let ex = (-f.vz - self.weights.touchdown_vz_ok).max(0.0);
1322                slam += ex * ex;
1323            }
1324        }
1325        let touchdown_vz = self.weights.touchdown_vz * slam * dt;
1326
1327        let mut da2_hip = 0.0;
1328        for &i in &self.hip_yawroll_idx {
1329            da2_hip += (state.last_action[i] - state.prev_action[i]).powi(2);
1330        }
1331        let action_rate_hipz_hipx = self.weights.action_rate_hipz_hipx * da2_hip * dt;
1332
1333        let body_ang_vel = self.weights.body_ang_vel * (w[FWD].powi(2) + w[LAT].powi(2)) * dt;
1334        let lin_vel_z = self.weights.lin_vel_z * v[UP].powi(2) * dt;
1335
1336        // Soft joint-position-limit penalty (soft band at 90% of the hard limit).
1337        let mut lim_pen = 0.0;
1338        for i in 0..NUM_JOINTS {
1339            let (lo, hi) = self.robot.joints[i].pos_limit;
1340            let (lo, hi) = (lo * 0.9, hi * 0.9);
1341            let q = state.joint_pos[i];
1342            lim_pen += (q - hi).max(0.0) + (lo - q).max(0.0);
1343        }
1344        let dof_pos_limits = self.weights.dof_pos_limits * lim_pen * dt;
1345
1346        let mut jv2 = 0.0;
1347        for i in 0..NUM_JOINTS {
1348            jv2 += state.joint_vel[i].powi(2);
1349        }
1350        let dof_vel = self.weights.dof_vel * jv2 * dt;
1351
1352        // --- foot-contact shaped terms ---
1353        let moving = !standing;
1354        // Forward-progress gate for the stepping BONUSES (air_time, single-support
1355        // bonus). Without it the policy farms those bonuses by stepping IN PLACE
1356        // (v≈0) — it overcooked into marching, abandoning forward tracking.
1357        // progress = clamp((v·cmd)/|cmd|², 0, 1): 1 when the base moves at the
1358        // commanded velocity, 0 when stationary/backward. So a stepping bonus is
1359        // only paid when the steps actually carry the robot toward the command.
1360        let cmd_sp2 = cmd.vx * cmd.vx + cmd.vy * cmd.vy;
1361        let progress = if cmd_sp2 > 1e-6 {
1362            ((v[FWD] * cmd.vx + v[LAT] * cmd.vy) / cmd_sp2).clamp(0.0, 1.0)
1363        } else {
1364            0.0
1365        };
1366        // Air time: reward the completed swing duration at touchdown (capped), so
1367        // any reasonable step is encouraged — only when commanded to move. (The old
1368        // `air_time − 0.5` form was negative for sub-0.5 s steps, i.e. it *punished*
1369        // this small robot's normal-cadence stepping.)
1370        // Pay the completed swing duration ONLY at an ALTERNATING touchdown
1371        // (f.alt_step). This is the unfarmable core of the gait: a foot held up
1372        // forever never lands (no reward); hopping on one foot earns nothing on
1373        // the repeat; only L→R→L→R stepping pays. Capped at 0.4 s/step.
1374        let mut air = 0.0;
1375        for f in &state.feet {
1376            if f.alt_step {
1377                air += f.air_time.min(0.4);
1378            }
1379        }
1380        let air_time = if moving {
1381            self.weights.air_time * air * dt * progress
1382        } else {
1383            0.0
1384        };
1385
1386        // Flight penalty: both feet off the ground = hopping/bounding, not walking.
1387        let flight = if state.feet.iter().all(|f| !f.contact) {
1388            self.weights.flight * dt
1389        } else {
1390            0.0
1391        };
1392
1393        // Gait-phase shaping (while moving). A *bonus* for stepping (air_time) gives
1394        // no exploration pressure — you only collect it AFTER you already step — so
1395        // from a shuffle the policy never discovers the first step. And a settle
1396        // BONUS for double-support actively rewarded the shuffle (measured: v40 sat
1397        // in permanent double-support, air_time stuck at 0). The pressure must come
1398        // from making NOT-stepping costly. So this term PENALIZES both degenerate
1399        // modes and leaves only alternating stepping unpunished:
1400        //   contacts==2 (permanent double-support = slide-shuffle) → penalty,
1401        //   contacts==1 but the airborne foot is HELD (air_time > MAX_SWING, i.e. a
1402        //     one-foot statue — the other hack) → penalty,
1403        //   contacts==1 with an ACTIVE swing (air_time ≤ MAX_SWING) → 0 (allowed),
1404        //   contacts==0 (flight) → 0, handled by `flight`.
1405        // A brief double-support SETTLE between steps costs little (a few steps of
1406        // small penalty); only PERMANENT double- or single-support is expensive.
1407        // The reward for doing it right is the alternation-gated air_time above.
1408        let contacts = state.feet.iter().filter(|f| f.contact).count();
1409        let single_support = if moving {
1410            match contacts {
1411                2 => -self.weights.single_support * dt, // permanent double-support = shuffle
1412                1 => {
1413                    // One foot up: fine if it's an active swing, penalized if it's a
1414                    // held statue (foot airborne longer than a normal swing).
1415                    let held = state
1416                        .feet
1417                        .iter()
1418                        .any(|f| !f.contact && f.air_time > MAX_SWING_S);
1419                    if held {
1420                        -self.weights.single_support * dt
1421                    } else {
1422                        0.0
1423                    }
1424                }
1425                _ => 0.0, // flight: see `flight`
1426            }
1427        } else {
1428            // STANDING (command ~0): the inverse — reward BOTH feet planted,
1429            // penalize stepping. Without this the walking policy keeps lifting
1430            // feet / stamping in place at zero command (it drifts + fidgets,
1431            // since nothing rewarded standing still). Now "step when told to move,
1432            // plant when told to stand" is symmetric.
1433            match contacts {
1434                2 => self.weights.single_support * dt, // both feet planted = good
1435                1 => -self.weights.single_support * dt, // stepping while told to stand = bad
1436                _ => 0.0,
1437            }
1438        };
1439
1440        // Extra "balance, don't step" pressure at stand (NEGATIVE weight, 0 = off;
1441        // BIPED_STAND_PLANTED_W): per airborne foot per step while the command is
1442        // standing. Stacks on the binary standing branch of `single_support`
1443        // above. Sized so quiet ankle/hip balancing beats fidget-stepping under
1444        // small pushes, while a genuine protective step (a few penalized steps)
1445        // stays far cheaper than falling (termination) under big ones.
1446        let stand_planted = if standing {
1447            let airborne = state.feet.iter().filter(|f| !f.contact).count() as f32;
1448            self.weights.stand_planted * airborne * dt
1449        } else {
1450            0.0
1451        };
1452
1453        // Slip: penalize horizontal foot speed while the foot is in contact.
1454        let mut slip = 0.0;
1455        for f in &state.feet {
1456            if f.contact {
1457                slip += f.planar_speed.powi(2);
1458            }
1459        }
1460        let foot_slip = self.weights.foot_slip * slip * dt;
1461
1462        // Ground-reaction smoothness: squared excess |ΔF| (body weights per
1463        // control step) above the deadband, per foot. Slam touchdowns and the
1464        // standing load-dither tremor both live here; gait weight transfer
1465        // stays inside the deadband. See the `force_rate` weight doc.
1466        let mut frate = 0.0;
1467        for f in &state.feet {
1468            let ex = (f.force_rate - self.weights.force_rate_deadband).max(0.0);
1469            frate += ex * ex;
1470        }
1471        let force_rate = self.weights.force_rate * frate * dt;
1472
1473        // Clearance: POSITIVE, capped reward for lifting an ACTIVE SWING foot above
1474        // its resting height, saturating at foot_clearance_target. Gated three ways
1475        // so it can't be farmed by holding one foot in the air (which is exactly how
1476        // the ungated version got hacked into a one-foot statue — 0 transfer):
1477        //   (1) f.contact == false   — only a lifted foot,
1478        //   (2) f.air_time < 0.45 s   — only an ACTIVE swing, not a held statue: a
1479        //       foot raised longer than a normal swing stops earning, so to keep
1480        //       collecting it must touch down (resetting air_time) and re-swing,
1481        //   (3) moving                — never at zero command (no stamping in place).
1482        const FOOT_REST_H: f32 = 0.035;
1483        const MAX_SWING_S: f32 = 0.45;
1484        // REWARDING THE STEP. While a step-up is cued and close, raise the
1485        // clearance target to the riser plus a margin, so "enough lift" means
1486        // enough to actually clear THIS step rather than a fixed 3 cm. The
1487        // reward saturates at the target (lift.min(1.0)), so raising it is
1488        // exactly "you must lift higher here" and nothing else changes.
1489        //
1490        // This reuses the existing term ON PURPOSE. foot_clearance was dropped
1491        // once because a static foot-height reward got hacked into a one-foot
1492        // statue (foot held up to farm it; zero transfer, MuJoCo fell in
1493        // 0.66 s). The guards added in response -- swing-only, air_time <
1494        // 0.45 s so a held foot stops earning, moving-gated, capped -- are
1495        // right here and apply unchanged. A fresh "reward crossing a step"
1496        // term would have none of them.
1497        const STEP_CLEAR_MARGIN: f32 = 0.05;
1498        let clear_target = if stepping && state.step_cue.height > 0.0 {
1499            (state.step_cue.height + STEP_CLEAR_MARGIN)
1500                .max(self.weights.foot_clearance_target)
1501        } else {
1502            self.weights.foot_clearance_target
1503        };
1504        let mut foot_h = 0.0;
1505        for f in &state.feet {
1506            if !f.contact && f.air_time < MAX_SWING_S {
1507                let lift = (f.height - FOOT_REST_H).max(0.0) / clear_target;
1508                foot_h += lift.min(1.0);
1509            }
1510        }
1511        let foot_clearance = if moving {
1512            self.weights.foot_clearance * foot_h * dt
1513        } else {
1514            0.0
1515        };
1516
1517        // Flat foot: penalize the squared sole tilt of any foot in contact, so the
1518        // robot plants its whole sole rather than balancing on a toe/heel/edge.
1519        // UNGATED (AGILE feet_roll_l2 parity): penalize sole tilt on ALL feet,
1520        // not just loaded ones. The contact-gated form left swing-foot posture
1521        // free, and the learned policy exploited it (hard dorsiflexion — toes
1522        // pointing up through swing; functional-ish for toe-clearance but an
1523        // engine-flattered habit under box friction, and ugly).
1524        let mut tilt_sq = 0.0;
1525        for f in &state.feet {
1526            tilt_sq += f.tilt.powi(2);
1527        }
1528        let foot_orientation = self.weights.foot_orientation * tilt_sq * dt;
1529
1530        // WBC's `feet_yaw_mean_vs_base`: sum of squared yaw (in base frame) over
1531        // both feet — drives each foot to point in the base's forward direction.
1532        let mut yaw_sq = 0.0;
1533        for f in &state.feet {
1534            yaw_sq += f.yaw_rel_base.powi(2);
1535        }
1536        let feet_yaw_mean = self.weights.feet_yaw_mean * yaw_sq * dt;
1537
1538        // WBC's `feet_yaw_diff_l2`: squared wrapped yaw difference between the
1539        // two feet (splay / pigeon-toe). Base-relative yaws work here — the base
1540        // yaw cancels in the difference.
1541        let feet_yaw_diff = if NUM_FEET == 2 {
1542            let d = state.feet[1].yaw_rel_base - state.feet[0].yaw_rel_base;
1543            let d = (d + core::f32::consts::PI).rem_euclid(2.0 * core::f32::consts::PI)
1544                - core::f32::consts::PI;
1545            self.weights.feet_yaw_diff * d.powi(2) * dt
1546        } else {
1547            0.0
1548        };
1549
1550        // WBC's `feet_distance_from_ref` (lateral mode): penalise the absolute
1551        // deviation of the lateral stance width from `feet_distance_ref`. We
1552        // transform the foot-to-foot world XY difference into the base frame
1553        // using only its yaw component (base assumed near-upright).
1554        let feet_distance = if NUM_FEET == 2 {
1555            let dx = state.feet[0].pos_xy[0] - state.feet[1].pos_xy[0];
1556            let dy = state.feet[0].pos_xy[1] - state.feet[1].pos_xy[1];
1557            // Project (dx, dy) world into base frame using base yaw.
1558            let q = &state.base.orientation; // (x, y, z, w)
1559            let base_yaw =
1560                (2.0 * (q[3] * q[2] + q[0] * q[1])).atan2(1.0 - 2.0 * (q[1] * q[1] + q[2] * q[2]));
1561            let cy = base_yaw.cos();
1562            let sy = base_yaw.sin();
1563            // Inverse-yaw rotation: world → base.
1564            let lateral = -sy * dx + cy * dy;
1565            let err = lateral.abs() - self.weights.feet_distance_ref;
1566            // L1 error like WBC's default `norm="l1"`.
1567            self.weights.feet_distance * err.abs() * dt
1568        } else {
1569            0.0
1570        };
1571
1572        // Periodic gait clock (DENSE). Foot 0's cycle starts at `phase`, foot 1 is
1573        // offset half a cycle, so they alternate. Within a foot's cycle, the first
1574        // `gait_swing_ratio` is the SWING window (the foot should be airborne), the
1575        // rest is STANCE (it should be in contact). Each step, each foot earns the
1576        // weight if its actual contact matches its prescribed phase. This pays
1577        // every step (not just at touchdown), so the gradient pulls the foot up at
1578        // the right time even before a full step succeeds — the dense signal the
1579        // sparse air_time bonus lacked. Only while moving (no forced gait at stand).
1580        // Siekmann-style: each foot scores +1 when its contact MATCHES its phase
1581        // (airborne in swing / grounded in stance) and −1 when it MISMATCHES. The
1582        // −1 for contact-during-swing is the crucial part (my first version gave 0
1583        // there): it makes keeping a foot down during its swing window actively
1584        // COSTLY, so standing no longer farms the stance windows for free — the
1585        // only way to stop bleeding reward is to actually lift on schedule. The
1586        // −1 for airborne-during-stance also penalizes a held-up statue foot.
1587        let gait_clock = if moving {
1588            let sr = self.weights.gait_swing_ratio;
1589            let mut gc = 0.0;
1590            for (k, f) in state.feet.iter().enumerate() {
1591                let ph = (state.phase + 0.5 * k as f32).fract();
1592                let want_swing = ph < sr;
1593                let matched = if want_swing { !f.contact } else { f.contact };
1594                gc += if matched { 1.0 } else { -1.0 };
1595            }
1596            // PROGRESS-GATE the gait reward: on-schedule stepping only pays when the
1597            // steps actually carry the body toward the command. Without this the
1598            // policy farms gait_clock by marching IN PLACE (measured: v47 stepped
1599            // cleanly — 5 cm lifts, 8–9 touchdowns — but vx≈0.03 m/s). The gate
1600            // makes forward steps the only way to earn it (progress = (v·cmd)/|cmd|²).
1601            // The double-support penalty (single_support, ungated) still backstops
1602            // against simply standing, so it must step — now forward.
1603            self.weights.gait_clock * gc * dt * progress
1604        } else {
1605            0.0
1606        };
1607
1608        RewardBreakdown {
1609            track_lin_vel,
1610            track_ang_vel,
1611            upright,
1612            base_height,
1613            pose,
1614            bilateral_symmetry,
1615            action_rate,
1616            action_rate_hipz_hipx,
1617            body_ang_vel,
1618            lin_vel_z,
1619            dof_pos_limits,
1620            dof_vel,
1621            air_time,
1622            flight,
1623            single_support,
1624            stand_planted,
1625            foot_slip,
1626            force_rate,
1627            action_rate_rate,
1628            touchdown_vz,
1629            foot_clearance,
1630            foot_orientation,
1631            feet_yaw_mean,
1632            feet_yaw_diff,
1633            feet_distance,
1634            gait_clock,
1635        }
1636    }
1637
1638    /// Mirror error: pairs left/right joints via the spec's mirror permutation
1639    /// and accumulates the squared difference under the family's mirror sign
1640    /// (sagittal joints mirror equal, lateral joints mirror opposite).
1641    /// `lateral_scale` attenuates ONLY the mirror-opposite joints (hip_roll,
1642    /// hip_yaw, ankle_roll — `mirror_sign < 0`). Those are "symmetric" when
1643    /// `q_L = -q_R`, i.e. mirror images. Turning needs the opposite: both
1644    /// hip_yaws rotate the SAME way, so the error is `(q + q)^2 = 4q^2` — the
1645    /// worst case for that term. Measured on v26's weights, 0.2 rad of
1646    /// coordinated hip yaw costs ~0.005/step against a ~0.002 behaviour
1647    /// threshold, so a commanded turn is actively taxed for the one thing it
1648    /// must do. The sagittal terms (hip_pitch, knee, ankle_pitch) are what keep
1649    /// the gait even and are never attenuated.
1650    fn symmetry_error(&self, q: &[f32; NUM_JOINTS], lateral_scale: f32) -> f32 {
1651        let mut err = 0.0;
1652        for i in 0..NUM_JOINTS {
1653            let jr = self.robot.mirror[i];
1654            if jr <= i {
1655                continue; // count each L/R pair once
1656            }
1657            let e = (q[i] - self.robot.mirror_sign[i] * q[jr]).powi(2);
1658            err += if self.robot.mirror_sign[i] < 0.0 {
1659                lateral_scale * e
1660            } else {
1661                e
1662            };
1663        }
1664        err
1665    }
1666
1667    /// Whether the episode should terminate from a fall: excessive tilt, sunk too
1668    /// low (the anti-reward-hack floor), or a non-finite base. The env adds the
1669    /// separate time-out termination at [`Self::max_steps`].
1670    pub fn fell_over(&self, base: &BaseState) -> bool {
1671        !base.height.is_finite()
1672            || base.height < self.min_base_height
1673            || self.upright_cos(base) < self.tilt_limit.cos()
1674    }
1675}
